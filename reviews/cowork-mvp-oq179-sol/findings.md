# Cowork F3 MVP adversarial findings

This verdict was reached from the implementation and tests before reading the existing Opus leg. The contained-kiosk demo is not safe to release: an acknowledged lease can actuate after server revocation/expiry, the durable idempotency key aliases distinct invocations, and the kiosk gate trusts an arbitrary client claim.

## Attacks that did fail closed

- OQ-7 field integrity itself held: absent/malformed envelope fields fail the device shape check; an unknown/wrong `kid` has no usable key; and tampering `leaseId`, capability, target device, nonce, or expiry changes the verified preimage. The device verifies before acknowledgement/action, and acknowledgement independently requires the device key.
- A consumed/revoked/expired lease cannot be acknowledged again, and concurrent terminal result updates have a single database winner. Different tool-call ids also obtain separate durable rows.
- The database deletion primitives update outstanding rows before their FK cascade in one transaction. No lease row survives deletion; the end-to-end authority nevertheless survives in the already-acknowledged device copy as described in the first finding.
- The shared connector mount does not itself retain invocation fields, and the target-selection singleton is keyed by user/workspace/session. The C1 break is in durable lease-key convergence and missing workspace exposure, not mutable mount fields.
