## Loading, exports and types

**E2 — Optional peers, static leaves, additional asynchronous acquisition.** Use `peerDependencies` plus `peerDependenciesMeta: { "<package>": { "optional": true } }` for each published optional module. Provider leaves statically re-export the corresponding public namespace; separate `/loaders/<leaf>` entries use literal dynamic `import()` for composition. Do not use `optionalDependencies`: npm normally installs those, violating the bare-install goal. Keep the existing required contracts/events/Hono dependencies. Installation never downloads peers automatically through an install hook, starts a process, or discovers credentials. Deployments explicitly install selected peers and their normal transitive dependencies; llm-gateway already depends on llm-mesh.

| Alternative | ESM / TypeScript / bundler consequence | Decision |
|---|---|---|
| Static value re-export from `.` | ESM resolves/evaluates providers on root import; bundler tree-shaking cannot make native Node imports safe | Reject |
| Static values/types on module subpaths | Isolates the root and preserves synchronous imports, live bindings and identity; a missing selected peer fails native ESM linking | Select as the consumer API |
| Dynamic loaders on separate `/loaders/*` subpaths | Importing a loader is safe without its provider; calling it awaits acquisition with structured refusal | Select as an additional composition API |
| Type-only consumer imports from static leaves | Erased from consumer JS, but TypeScript must resolve the referenced provider declarations | Select with the explicit type boundary below |

`@sentropic/cluster-mesh` retains all 0.11 exports and adds cluster-mesh-owned `createClusterMeshModules`, `ClusterMeshModules`, `ClusterMeshModuleUnavailableError` and provider-free capability types. `createClusterMeshModules()` creates a registry for one composition root; its closed catalog has package/export IDs, accepted versions, load thunks and namespace adapters. No provider import or filesystem probe runs at construction. `modules.load(id): Promise<unknown>` is the common internal/public untyped acquisition path; typed leaf loaders below call it and return the original module namespace. There is no process-global service singleton. A root passes the same registry to its loaders and namespace preparation. Concurrent calls share one pending promise per export; successes and failures are cached for that registry. Changing installed packages requires a restart/new registry, not implicit hot installation or retry storms.

**E3 — Declaration isolation.** Root JS and the transitive root `.d.ts` graph have no static import/re-export or type reference to an optional peer or typed leaf. Root-only TypeScript consumers MUST compile without optional modules with both `skipLibCheck: false` and `true`. Provider leaves MUST use only `export * from '<provider-public-entry>'` in source and emitted declarations: no named value/type re-exports from peers. This preserves overloads, generics and nominal class identity without copied interfaces or async proxies. With h2a's `skipLibCheck: true`, missing peer declarations behind `export *` make the consumer's named import fail with “has no exported member” (TS2305), rather than relying on TS2307 inside the skipped declaration. A named re-export could silently become `any` and is forbidden. A separate typed loader returns `Promise<typeof import('<provider-public-entry>')>`; its supported type contract requires the peer's declarations even when skipped library checking suppresses a missing-module diagnostic. Only root and loader **JS** are safe without peers. No `any` shim or ambient fake package. Type-only `AccountPublic` access emits no enrollment runtime import. Build/test dependencies supply peers for declarations without making them published hard dependencies.

Every declared cluster-mesh export has explicit `types` and `import` conditions; no wildcard deep imports or new CJS guarantee. Support native Node ESM and TS NodeNext/Bundler resolution. Keep `sideEffects: false` and no top-level loader calls. Bundlers can still resolve literal dynamic imports while building an unused branch: the supported server bundle recipe externalizes optional peer package names **and their subpaths**, preserving runtime imports. h2a-runtime's tsup (esbuild) build MUST also externalize `@sentropic/cluster-mesh` and every `@sentropic/cluster-mesh/*` subpath, retaining imports anchored at the installed cluster package. Tree-shaking is an optimization, not installation isolation. Browser execution of Node provider/facade entries is not promised. A bundle that inlines a selected provider must have it installed at build time and preserve equivalent version evidence; the supported 0.12 path uses external peers.

## Refusal and F1 capability reporting

**E6 — Fail closed at the selected boundary.** Root and `/loaders/*` JS perform no provider resolution on import. Static leaves link/evaluate the selected provider immediately: a missing dependency/export in that static graph fails native ESM loading before the importing consumer's body executes; cluster-mesh cannot wrap it in its typed loader error. This does not detect Lot C's deferred auth imports. A type-only missing peer fails compilation instead. Static imports do not enforce registry enablement/version policy or update its cache; installed-version coherence relies on E8's release/install gates. Guarded activation uses loaders/composition: acquisition checks enablement, presence, version and export map before evaluating the provider, then runtime members before returning it; failures precede factory invocation. `loadGatewayAuth` and `loadGatewayAuthHono` additionally preload their selected auth peer graph before resolving, so callers can use them as startup preflight while retaining static constructors. Provider evaluation must be effect-free. No auto-install, fallback endpoint, missing-provider stub or silent `no-gw` selection. `stubGatewayConfig` is only the upstream test/config API, never a refusal fallback.

h2a already dynamically imports `@sentropic/h2a-runtime`; rejection of that existing import promise is the consumer's capture/diagnostic site for native static-link failures, consistent with its 0.97.3 startup fixes. Await and catch auth preflight in the same startup path before bind for deferred peers; a try/catch around a later constructor cannot catch an earlier static-link failure. Emit a sanitized dependency diagnostic and stop startup, rather than a 401/500 on the first authenticated request (or Lot C's unavailable 503).

The root-exported `ClusterMeshModuleUnavailableError extends Error` has `code: 'cluster_mesh_module_unavailable'`, `moduleId`, `packageName?`, `requiredRange?`, `installedVersion?`, `reason` and a local diagnostic `cause?`. Reasons are `disabled | not_installed | incompatible_version | export_unavailable | load_failed | source_unavailable`; no widening of 0.11's closed `GatedCapability` union is needed. Consumers recognize the error by its stable `code`, with structural checks before reading diagnostic fields; `instanceof` is not the cross-package recognition contract. Exact missing-module message template: `Cluster Mesh module "{moduleId}" is unavailable (not_installed). Install {packageName}@"{requiredRange}" and restart.` An absent selected gateway auth peer is `not_installed` naming that peer; its broken transitive graph or an evaluation exception is `load_failed`. Unreadable/malformed version evidence refuses as `incompatible_version`. Public diagnostics omit filesystem paths, credentials and raw causes; operations may log sanitized causes locally.

`modules.probe(): Promise<ModuleCapabilityMap>` explicitly resolves metadata/entry presence without evaluating provider code or constructing clients; it never activates a module. Resolution uses the same ESM conditions and package location as static leaves/loaders, finds the owning manifest without assuming an exported `package.json`, and rejects unverifiable metadata. Before probing, records are `{ availability: 'gated', state: 'unprobed' }`; compatible installed entries become `{ availability: 'available', state: 'installed' }`, successful registry acquisition becomes `loaded`, and refusal becomes `{ availability: 'gated', state: 'unavailable', reason, packageName?, requiredRange?, installedVersion? }`. Static imports alone remain unobserved by this registry. Availability is an acquirable contract, not account/auth/service readiness. A later loader failure demotes the record. Disabled/unknown entries never report available.

For gateway auth, probes, version checks and preflight resolve mcp-auth/jose or auth-hono **from the gateway package**, using the same ESM conditions/physical package instance as its deferred imports, not from cluster-mesh or the caller. Follow transitive dependencies from their respective owning packages. Service preflight evaluates the gateway-resolved `@sentropic/mcp-auth/hono` and `jose` graph (including oauth-verify/Hono); session preflight evaluates `@sentropic/auth-hono/middleware` and its graph. Probe remains metadata-only and cannot substitute for preflight. A compatible peer visible only to cluster-mesh cannot satisfy a missing or incompatible gateway-relative peer; root `/gateway` selection checks neither auth mode.

Add optional `modules` input to `createDegenerateClusterMesh` and optional `capabilities.modules` snapshot/getter backed by that registry. Absence remains explicit for old callers; legacy structurally typed mocks compile unchanged. F1 `localDevices`/`localProjection` stay getters over current binding availability, with legacy defaults unchanged; do not overload them with installation state. Preserve F2–F7 as shipped by 0.11.0, including injected NHI, device denial, projection expiry and custody verification export; F5 is not implemented by this design. Readiness/auth checks remain distinct from package availability.

## Namespace and version compatibility

**E7 — One mounting authority, shared provider identities.** Existing `createClusterMeshPlugin({ runtime, namespaces, mounts })` and `createNamespaceRegistry` stay synchronous and authoritative. New owned async `/compose/gateway:createGatewayNamespaceModule` and `/compose/llm-mesh:createLlmMeshNamespaceModule`, plus E5's MCP wrapper, load only enabled modules at composition startup, inject host ports and return ordinary `ClusterMeshHonoNamespaceModule` objects. The LLM wrapper requires an injected router factory: `createLlmMeshRouter` lives in `api/src/routes/namespaces/llm-mesh-router.ts`, not a provider export. Its host callback receives the acquired namespace and neutral context/receipt ports; never import application source or copy its router. Disabled preparation does not resolve peers. No async `createRouter` mutation, second dispatcher or competing registry. Product factories use these wrappers without also mounting the old router. Loaders and preparation share the registry/cache; static leaves share provider identity through ESM's module cache, without registry participation. Gateway bridge acquisition is explicit and mode-specific, never part of root `/gateway` acquisition.

When a Lot C auth mode is selected, `/compose/gateway` MUST await the corresponding auth loader/preflight, including the gateway-relative peer graph, before returning a mountable module. Static-leaf consumers MUST document and await `loadGatewayAuth(modules)` or `loadGatewayAuthHono(modules)` before binding any listener; an equivalent gateway-provided preflight hook is acceptable only if it checks/evaluates the same graph and is qualified in B3. Importing the auth leaf or constructing its verifier is insufficient because Lot C defers peer imports until verification. A host-injected custom `CallerAuthPort` selects no Lot C auth peer. Missing, incompatible or unloadable selected peers fail startup; no listener opens and no test request is needed to expose the failure.

Keep `/llm-mesh`, `/gw` and `/mcp` namespace keys, existing product mount projections/remaps and IdP boundaries unchanged; the npm `/gateway` subpath does not create an HTTP `/gateway`. Reuse the injected product `createLlmMeshRouter`, gateway's exported `createGatewayRouter` and existing verified-context/receipt/domain-authorization gates. Required enabled namespace preparation fails startup before binding a listener when its peer is missing; an intentionally disabled namespace stays unmounted (existing 404 behavior). A direct SDK loader rejects its promise with E6's error. Existing single-author cutover/rollback and one logical MCP authority per generation remain D11/D15 gates. `GatewayNamespace = 'gw' | 'no-gw'`, M05 `launchContext.gateway` and `session:relaunch:gateway` authorization are unchanged: installation or capability availability never enables gateway privilege. Missing gateway code cannot silently select `no-gw`. Track standalone stdio is a deliberate standalone command; a generation composes its read handlers once, not one new Track authority per session.

**E8 — Version envelope and coherent release tuple.** For cluster-mesh 0.12.x, declare optional peers llm-mesh `>=0.21.2 <0.22.0` and llm-gateway `>=0.18.0 <0.19.0`, excluding prereleases. Lot C's 0.18.0 breaks auth/port types: reject 0.17.x rather than silently supporting two shapes. Gateway's actual mesh dependency must intersect the mesh range and resolve to the same physical instance as cluster-mesh's leaves; a second copy is incompatible even at the same version. Loaders/probes validate name/version/export presence and instance coherence, refusing version/instance skew as `incompatible_version`; only loaders additionally validate runtime members after evaluation. Static re-exports cannot run that check before ESM linking: packed qualification and consumer install gates must check the same tuple before launch. Forcing an unsupported install is outside the static contract; no runtime version guard is claimed for direct imports.

Duplicate cluster-mesh installations can make `instanceof ClusterMeshModuleUnavailableError` false even for the same version. Recognition by `code === 'cluster_mesh_module_unavailable'` remains the consumer contract while diagnosing that invalid topology; constructor identity is not a reliable refusal discriminator.

**Normative consumer installation topology.** Every manifest that declares cluster-mesh and imports one of its leaves MUST also declare that leaf's selected peers at the qualified versions. A leaf's bare provider import resolves from cluster-mesh's **physical location**, not from the application or a separately installed runtime package. Manifest declarations alone are insufficient: the deployed tree MUST contain exactly one physical cluster-mesh instance, with selected peers reachable from it, and one llm-mesh instance shared by cluster-mesh and gateway. Reject nested 0.9/0.12 copies and distinct pnpm peer variants, even when their version strings match. Align peer contexts across consuming manifests and prove realpath/module identity in the installed artifact; a workspace lockfile or successful first-party import does not prove this invariant.

**Runtime topology guard (conductor decision, 2026-09-24, reversible).** Install gates alone leave static-leaf consumers unchecked at runtime (h2a observed npm silently keeping nested gateway copies). Every leaf, loader and compose module therefore first imports a side-effect guard, then its `export *`; this amends E3's "only `export *`" rule by exactly that one import and the leaves are declared in `sideEffects`. Each evaluated cluster-mesh copy pushes a unique token (with realpath/version for diagnostics only) into the process-global `Symbol.for('@sentropic/cluster-mesh/instances')` registry; more than one token is a duplicate, which stays correct under `--preserve-symlinks`, `npm link` and pnpm peer variants. The guard also compares the llm-mesh realpath resolved from cluster-mesh's location with the one resolved from the installed gateway's location, metadata-only and without evaluating either. It is memoized per copy count and throws `ClusterMeshTopologyError` (`code: 'cluster_mesh_topology_invalid'`, `reason: duplicate_instance | divergent_llm_mesh | incompatible_version | not_installed`), whose message names the conflicting paths for the operator; there is no warning-only path. The root registers its copy without checking and exports `verifyClusterMeshTopology({ require? })`, an explicit earlier preflight that additionally enforces the accepted ranges. Limits: the guard is per process, so two processes each loading a different but self-consistent copy remain covered by packed-qualification/consumer-install gates; under `--preserve-symlinks` two distinct llm-mesh instances can share one realpath and are not detectable without importing both.
