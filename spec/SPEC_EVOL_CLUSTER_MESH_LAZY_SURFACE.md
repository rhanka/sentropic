The control-plane D1/D3/D6/D13–D16, namespace inventory and r13 implementation evidence remain authoritative.

**E1 — Dependency direction and integration ownership.** Consumers integrate these capabilities through cluster-mesh; llm-mesh, llm-gateway, MCP and other domain packages remain independently usable/publishable and never import or depend on cluster-mesh, including in their declarations. Cluster-mesh owns composition, loading and capability diagnostics; domain implementations, configuration semantics, secret storage and authorization remain with their current owners. “Embed all lazily” means ship the integration catalog and adapters for every capability, with optional installation and demand-driven evaluation; it does not mean bundle every provider. h2a keeps collaboration/tool authorization and its host adapters under D3. Standalone h2a composes cluster-mesh locally without requiring a remote control plane.

## Loading, exports and types

**E2 — Optional peers, explicit subpaths, asynchronous acquisition.** Use `peerDependencies` plus `peerDependenciesMeta: { "<package>": { "optional": true } }` for each published optional module and literal dynamic `import()` per supported public export. Do not use `optionalDependencies`: npm normally installs those, violating the bare-install goal. Keep the existing required contracts/events/Hono dependencies. Installation never downloads peers automatically through an install hook, starts a process, or discovers credentials. Deployments explicitly install only selected peers, including their normal transitive dependencies; llm-gateway already depends on llm-mesh.

| Alternative | ESM / TypeScript / bundler consequence | Decision |
|---|---|---|
| Static value re-export from `.` | ESM resolves/evaluates providers on root import; bundler tree-shaking cannot make native Node imports safe | Reject |
| Static values on module subpaths | Isolates the root, but importing a missing leaf throws an untyped resolution error; synchronous constructors cannot honestly be async proxies | Reject |
| Optional peers + dynamic loaders on explicit subpaths | Importing a loader is safe; calling it awaits the provider once, preserving native identities and synchronous APIs after acquisition | Select |
| Type-only re-exports on selected subpaths | Erased from JS, but TypeScript must resolve the referenced provider declarations | Select with the explicit type boundary below |

`@sentropic/cluster-mesh` retains all 0.11 exports and adds cluster-mesh-owned `createClusterMeshModules`, `ClusterMeshModules`, `ClusterMeshModuleUnavailableError` and provider-free capability types. `createClusterMeshModules()` creates a registry for one composition root; its closed catalog has package/export IDs, accepted versions, load thunks and namespace adapters. No provider import or filesystem probe runs at construction. `modules.load(id): Promise<unknown>` is the common internal/public untyped acquisition path; typed leaf loaders below call it and return the original module namespace. There is no process-global service singleton. A root passes the same registry to its loaders and namespace preparation. Concurrent calls share one pending promise per export; successes and failures are cached for that registry. Changing installed packages requires a restart/new registry, not implicit hot installation or retry storms.

**E3 — Declaration isolation.** Root JS and the transitive root `.d.ts` graph have no static import/re-export or type reference to an optional peer or typed leaf. Root-only TypeScript consumers MUST compile without any optional module, with `skipLibCheck: false`. Every typed leaf exposes `export type` aliases to the provider's public types (including class instance types), never copied interfaces. Its loader returns `Promise<typeof import('<provider-public-entry>')>`. Importing that leaf's JS is safe without the peer; typechecking that leaf or its type-only imports requires its peer and provider-required declaration dependencies, and otherwise deliberately reports a normal TypeScript missing-module diagnostic. There is no `any` shim or ambient fake package. Type-only `AccountPublic` access emits no enrollment runtime import. Build/test dependencies supply peers for declaration generation, without moving them into published hard dependencies.

Every declared cluster-mesh export has explicit `types` and `import` conditions; no wildcard deep imports or new CJS guarantee. Support native Node ESM and TS NodeNext/Bundler resolution. Keep `sideEffects: false` and no top-level loader calls. Bundlers can still resolve literal dynamic imports while building an unused branch: the supported server bundle recipe externalizes optional peer package names **and their subpaths**, preserving runtime imports. Tree-shaking is an optimization, not installation isolation. Browser execution of Node provider/facade entries is not promised. A bundle that inlines a selected provider must have it installed at build time and preserve equivalent version evidence; the supported 0.12 path uses external peers.

## Refusal and F1 capability reporting

**E6 — Fail closed on acquisition.** Importing `.` or any loader JS performs no provider resolution and never fails just because a peer is absent. The first explicit loader/namespace preparation call checks enablement, package presence, supported version and package export map, then evaluates the selected public entry and validates required runtime members before returning it. It rejects before any factory invocation or provider effect when these checks fail; provider module evaluation must itself remain free of effects. Do not auto-install, fall back to a direct provider/remote endpoint, return stubs, or turn an absent gateway into a direct launch. `stubGatewayConfig` stays reachable for existing tests; it is never a missing-provider fallback.

The root-exported `ClusterMeshModuleUnavailableError extends Error` has `code: 'cluster_mesh_module_unavailable'`, `moduleId`, `packageName?`, `requiredRange?`, `installedVersion?`, `reason` and a local diagnostic `cause?`. Reasons are `disabled | not_installed | incompatible_version | export_unavailable | load_failed | source_unavailable`; no widening of 0.11's closed `GatedCapability` union is needed. Exact missing-module message template: `Cluster Mesh module "{moduleId}" is unavailable (not_installed). Install {packageName}@"{requiredRange}" and restart.` A transitive dependency failure, evaluation exception or broken package becomes `load_failed`, never falsely `not_installed`. Unreadable/malformed version evidence refuses as `incompatible_version`. Public diagnostics omit filesystem paths, credentials and raw causes; operations may log sanitized causes locally.

`modules.probe(): Promise<ModuleCapabilityMap>` explicitly resolves metadata/entry presence without evaluating provider code or constructing clients; it never activates a module. Resolution uses the same ESM import conditions and package location as loading, finds the owning manifest without assuming an exported `package.json`, and rejects unverifiable metadata. Before probing, records are `{ availability: 'gated', state: 'unprobed' }`; compatible installed entries become `{ availability: 'available', state: 'installed' }`, successful acquisition becomes `loaded`, and refusal becomes `{ availability: 'gated', state: 'unavailable', reason, packageName?, requiredRange?, installedVersion? }`. Availability means acquirable package contract, not enrolled account, authorization or ready service. A later import failure demotes the record. Disabled entries stay gated even when installed; unknown/unsupported entries never report available.

Add optional `modules` input to `createDegenerateClusterMesh` and optional `capabilities.modules` snapshot/getter backed by that registry. Absence remains explicit for old callers; legacy structurally typed mocks compile unchanged. F1 `localDevices`/`localProjection` stay getters over current binding availability, with legacy defaults unchanged; do not overload them with installation state. Preserve F2–F7 as shipped by 0.11.0, including injected NHI, device denial, projection expiry and custody verification export; F5 is not implemented by this design. Readiness/auth checks remain distinct from package availability.

## Namespace and version compatibility

**E7 — One loading path, one mounting authority.** Existing `createClusterMeshPlugin({ runtime, namespaces, mounts })` and `createNamespaceRegistry` stay synchronous and authoritative. New owned async `/gateway:createGatewayNamespaceModule` and `/llm-mesh:createLlmMeshNamespaceModule`, plus E5's MCP wrapper, load only explicitly enabled modules at composition startup, inject host ports into owner router factories, and return ordinary `ClusterMeshHonoNamespaceModule` objects. The LLM wrapper requires an injected router factory: current `createLlmMeshRouter` lives in `api/src/routes/namespaces/llm-mesh-router.ts`, not any llm-mesh public export. Its host callback receives the acquired LLM namespace and neutral context/receipt ports; the package never imports application source or copies its router. Disabled modules do not resolve/load peers. Async preparation is first use; no async `createRouter` mutation, second HTTP dispatcher or competing route registry. Product namespace factories adapt their wiring to these wrappers when migrated; they must not also instantiate/mount the old provider router. SDK loaders and HTTP preparation share the same registry/cache and provider exports. Adapter selection is configuration, not provider discovery on a request path.

Keep `/llm-mesh`, `/gw` and `/mcp` namespace keys, existing product mount projections/remaps and IdP boundaries unchanged; the npm `/gateway` subpath does not create an HTTP `/gateway`. Reuse the injected product `createLlmMeshRouter`, gateway's exported `createGatewayRouter` and existing verified-context/receipt/domain-authorization gates. Required enabled namespace preparation fails startup before binding a listener when its peer is missing; an intentionally disabled namespace stays unmounted (existing 404 behavior). A direct SDK loader rejects its promise with E6's error. Existing single-author cutover/rollback and one logical MCP authority per generation remain D11/D15 gates. `GatewayNamespace = 'gw' | 'no-gw'`, M05 `launchContext.gateway` and `session:relaunch:gateway` authorization are unchanged: installation or capability availability never enables gateway privilege. Missing gateway code cannot silently select `no-gw`. Track standalone stdio is a deliberate standalone command; a generation composes its read handlers once, not one new Track authority per session.

**E8 — Version envelope.** For cluster-mesh 0.12.x accept llm-mesh `>=0.21.2 <0.22.0`, llm-gateway `>=0.17.1 <0.18.0`, mcp-auth/mcp-platform `>=0.2.0 <0.3.0`, and Track MCP `>=0.97.6 <0.98.0`; exclude prereleases. Validate manifest name/version, requested export presence and required runtime members before use. Gateway acquisition additionally verifies that its llm-mesh dependency meets the same range and resolves to the same real package instance as cluster-mesh's llm-mesh entries; a different instance refuses as `incompatible_version` even when version strings match, with a diagnostic recommending dependency deduplication. The exported facade/member contract, not semver alone, is the gate. Provider patch updates within an accepted range require floor/latest compatibility tests; supporting another 0.x minor requires an explicit cluster-mesh minor and new matrix evidence. Exact deployed versions are lockfile-pinned. Other catalog peers use the same tested floor/next-minor ceiling rule, frozen against their actual public export contracts in implementation lot B4 before activation.

No llm-mesh/llm-gateway source or version change is inherently needed: the required symbols and subpaths already exist and gateway's `^0.21.0` dependency admits the chosen llm-mesh floor. Do not add a cluster-mesh dependency to either package. The reviewed 0.11.0 F1–F7 change lands before implementation; recheck release registry tags and choose the next free minor if 0.12.0 has already shipped. Publish only after packed-install tests, CI and conductor approval. mcp-auth currently declares `@sentropic/oauth-verify: file:../oauth-verify`; an installed public tarball must prove this is resolved correctly. If it is not, MCP activation needs a separately scoped mcp-auth packaging fix/bump, not a cluster-mesh vendoring workaround or a claimed successful install.

## Consumer migration handoff to h-cond

**E9 — Migration text.** “After cluster-mesh 0.12 is qualified, declare cluster-mesh as the source integration dependency and explicitly provision the selected compatible llm-mesh/gateway/Track peers in h2a's deployable package manifests and lockfile. Optional peers are not installation bundles: retain the package-level declarations needed for deterministic resolution, including h2a-runtime's current llm-mesh resolution guard. Replace every production/type/test import in E4 with its cluster-mesh leaf. Await loaders inside the command/service startup boundary before constructing adapters, routing profiles or facade instances; move module-scope values such as routing profiles and Track tool descriptors behind that boundary. Do not introduce top-level await into generic CLI boot, or eagerly load llm-mesh for unrelated commands. After acquisition, use the original synchronous provider functions/classes. Catch the typed unavailable error at the CLI boundary, show its actionable message and return failure for the requested capability. Never continue with an unrequested execution mode.”

Example sequence inside an existing async LLM startup: import `createClusterMeshModules` from `@sentropic/cluster-mesh`, `loadLlmMesh` from `/llm-mesh`, `loadLlmMeshFacade` from `/llm-mesh/facade`, and `loadGateway` from `/gateway`; create one registry, then await the loaders, then use `createLlmMesh`, `createLlmMeshFacade` and `createGatewayRouter` from their results with the existing host ports. Import `RoutePlanner` and `AccountPublic` only with `import type` from their E4 leaves. Thread that registry through helpers; do not replace domain ownership or copy routing defaults into h2a. Track tools/server initialization similarly awaits `/mcp/track` and receives descriptors/handlers; its CLI standalone command retains the canonical `serveTrackMcpStdio` lifecycle.

h-cond owns changes in both h2a runtime and app gateway, the MCP files above, and `packages/h2a-runtime/src/{llm-mesh.test.ts,llm-mesh-resolution.test.ts,llm-gateway-runtime/native-tools.test.ts}` plus their affected call sites/tests. Acceptance: source scan has zero direct production or type imports of the measured Sentropic modules (package metadata assertions in resolution tests may name them); all entry-point mappings compile; runtime identity, account ownership, routing/metering/settlement and MCP descriptors/lifecycle remain equivalent; unrelated CLI commands run without LLM peers; requested missing capabilities refuse before effects. Keep optional-package installation explicit, and remove old direct integration code in the same cutover. Roll back by restoring the previous h2a artifact and lockfile, never by maintaining two route authors or runtime fallback integrations.
