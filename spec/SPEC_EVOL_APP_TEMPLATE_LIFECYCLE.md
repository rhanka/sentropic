## 1. Q1 — "Published contract" scope (D11 surface)
The D11-governed surface = the exported public API of each non-private `@sentropic/*` package (the `exports` map's TYPES + signatures + discriminated-union shapes + **Svelte component prop contracts**). Tiers:
- **Strict (snapshot + class-gate + migration notes)** — `contracts` (TenantContext/AuthzContext/CostContext/IdempotencyKey/CheckpointVersion/EventEnvelope), `events` (StreamEvent union, WireVersion), `chat-core` (8 ports), `comments` (CommentStore/CommentEventSink), `chat-server` (ChatServerDeps + ports **+ its HTTP/SSE wire DTOs** — wire shapes a `.d.ts` snapshot can miss), `auth-hono` (`./contracts`+ports **+ OIDC/route wire**), `chat-ui`/`auth-ui` (`.svelte.d.ts` prop contracts), `flow` (the ~30 ports, the moment it adopts contracts).
- **Contract-bearing-light (snapshot yes, strict class-gate no; CLI/JSON surfaces versioned by convention)** — `harness` (emits **VerificationRun JSON ingested by track** = a cross-tool contract; + CLI verb/flag surface), `cli`/`build-cli` (CLI flags + **`build-cli/templates/**` + the `./manifest` export** = public app-template/scaffold surface), `llm-mesh`/`skills` (SDK/types). CLI-flag and emitted-JSON contracts are NOT visible to a TS `.d.ts` snapshot → versioned by convention + a golden-JSON test where ingested.
- **Internal (freely mutable)** — anything outside the `exports` map; api-local types (e.g. ARCH-14 `control.event_outbox` columns); `"private": true` packages.

## 2. Q2 — Semver semantics (0.x → 1.0), full breaking/additive taxonomy
- **0.x rule (caret-aligned)**: **MINOR `0.N→0.(N+1)` = BREAKING**; **PATCH `0.N.x→0.N.(x+1)` = NON-breaking**. Correct vs npm: `^0.1.1` ⇒ `>=0.1.1 <0.2.0` (the actual ranges — `comments→contracts ^0.1.1`, `chat-server→chat-core ^0.1.2` while chat-core is 0.1.5: patches flowed as intended). *Footnote: first publish at `0.1.0` (caret on `0.0.x` pins the exact patch).*
- **BREAKING (minor)**: remove/rename/retype an export; add a REQUIRED param or field; narrow an input type; **change a consumed union/enum member**; **ADD a member to a CONSUMED union/enum** (e.g. `StreamEvent` — breaks exhaustive `switch`/strict decode at consumers and on the wire); **add a REQUIRED METHOD to a port interface** (breaks implementers, not callers).
- **NON-breaking (patch)**: add an export; add an OPTIONAL field/param; widen input / narrow output staying assignable; internal fix. **Optional-additive on WIRE types is patch ONLY GIVEN the must-ignore-unknown-fields rule below.**
- **Must-ignore-unknown-fields (the runtime precondition)**: every wire/event validator (zod decoders for `StreamEvent`, `EventEnvelope`, chat-server DTOs, comment events) MUST tolerate unknown fields (non-strict parse). This is what makes "optional-additive = patch" safe at RUNTIME (a strict validator silently downgrades any optional-additive to de-facto breaking) and is the operational meaning of `WireVersion=1` holding.
- **Behavioral contract changes** (invisible to a type snapshot — e.g. "the store now honors an optional executor when present") STILL require a CHANGELOG entry even when classed PATCH.
- **Graduation to 1.0.0**: per-package, when the surface is stable AND a real external (non-monorepo) consumer depends on stability. `@sentropic/contracts` first (foundation). Post-1.0 = standard semver. **Timing is owner-grade (§3 batch).**

## 3. Q3 — Migration notes + CI gate (de-hyped)
- **Convention**: per-package `CHANGELOG.md`; a `## <version> — BREAKING` section is REQUIRED on every minor (0.x) / major (1.x); template `plan/MIGRATION_TEMPLATE.md`.
- **CI gate (honest scope)**: extend `enforce-package-bump` to a **public-surface snapshot** per package. CI AUTOMATICALLY enforces: *surface changed → a version bump occurred AND a CHANGELOG entry exists; if the bump is a minor/major → a BREAKING section exists.* CI does **NOT** auto-classify breaking-vs-additive (the hard 20%) — **bump-class correctness stays a review judgment** (heuristics may come later). (Avoids quoting the gate as automation it isn't.)
- **Snapshot mechanics (feasible, specified)**: for dist-typed TS packages (contracts/events/… — NO committed `dist/`), CI runs the existing `make build-<pkg>` then extracts a per-subpath `.d.ts` digest **walking the FULL `exports` map** (auth-hono ~15 subpaths, chat-ui ~50 — a single-entry api-extractor rollup is insufficient; `tsc --emitDeclarationOnly`/ts-morph per subpath). For Svelte, **diff the COMMITTED `.svelte.d.ts` files** (chat-ui ships ~17; require auth-ui to ship them too) — no svelte2tsx machinery needed. Commit a `surface.json` artifact per package; CI diffs it. Extend coverage beyond `src/**` to `package.json` `exports`/dep+peer ranges/`files`, and `build-cli/templates/**`.

## 4. Q4 — `file:` masking → packed-form binding + pack/install smoke + publish-lag (snapshot alone is NOT enough)
- **Packed-form ≠ repo-form**: chat-ui rewrites its `package.json` at pack time (`make pack-chat-ui`, `scripts/make-publish-pkgjson.mjs` → dist-form exports). A snapshot from the REPO exports map proves nothing about the PUBLISHED exports → for dist-rewrite packages the surface snapshot + validation MUST bind to the `npm pack` output (generalize the existing `pack-chat-ui` tarball check). The repo already paid for this once (chat-ui 0.11.0 dist saga).
- **Pack/install smoke**: build+pack changed packages, install into a temp generated app / fixture using the DECLARED ranges, then typecheck + import each public subpath. This is the real guard the `file:` protocol erases.
- **Range-lint** covers package deps, peer deps, the `file:` app consumers, and `build-cli` templates; AND checks npm `latest` per package — external consumers resolve against the REGISTRY, and publishes have silently lagged merges (#244) → name publish-lag as a tracked failure mode.
- **Fix the live issues**: the stale `build-cli` template ranges (`chat-ui:^0.1.1`) must be regenerated to current ranges (or generated from live versions); replace `cowork-bridge`'s `chat-ui:"*"` with an explicit range. The `^0.3||^0.4||^0.5` multi-minor tolerance is a **peerDep-ONLY** pattern (a regular dep risks dual-install) and MUST come with compatibility tests across each supported minor (else it is an assertion, not evidence).

## 5. Q5 — App-template lifecycle + schema-version separation
- **Template versioning** (`control.app_templates (app_slug, version)`, ARCH-01): a blueprint change bumps the TEMPLATE version using the same breaking/additive discipline applied to the BLUEPRINT surface (new required capability/binding = breaking; additive-optional = non-breaking). Templates aren't npm-resolved → the caret rationale is decorative there; this is a CONVENTION.
- **Instance upgrade/rollback**: an `app_instance` pins a template version; upgrade = rebind to a newer version (apply the template's migration notes to instance state); rollback = rebind to the prior version (safe only across non-breaking deltas, else needs a down-migration). `desired_state` records the target; the reconciler moves `observed_state`.
- **Schema versions ≠ package semver**: `payloadSchemaVersion` (DD8) and `blueprintSchemaVersion` (ARCH-01) are artifact-level schema versions evolving independently of package `version`, governed by the same additive-preferred + must-ignore discipline inside the jsonb.
- **⚠️ OWNER-GRADE**: the **guarantees** around published-template immutability + upgrade/rollback/down-migration are as socially hard to unwind as `contracts@1.0` once EXTERNAL app instances exist → §6 batch.

## 6. Q6 — The 3 deferred mutations, classified + gated
- **comments-executor (ARCH-14)**: required executor/txn param = BREAKING (`@sentropic/comments` 0.1→0.2 minor + migration note); **OPTIONAL executor param = PATCH (recommended)** — non-breaking both directions (TS structural), do NOT leak a Drizzle/pg executor into the generic package, AND add a CHANGELOG entry for the BEHAVIORAL change even as patch.
- **EventEnvelope `traceId?` (ARCH-14)**: AVOIDED (internal outbox columns). If lifted: OPTIONAL `traceId?`/`origin?` = PATCH to `@sentropic/contracts` (precedent: `redactedFields?`/`signature?` already optional) — **conditional on the must-ignore wire rule** (else a strict envelope validator makes it de-facto breaking).
- **flow-adopts-contracts**: importing `contracts` as an internal dep is NOT breaking; threading REQUIRED `TenantContext` through public flow ports IS breaking → `@sentropic/flow` 0.1→0.2 **breaking-minor** (not "major-line") + migration note.
