## Transfers and boundaries

Move to package-owned Vue compositions: generic history staging/scroll, draft/action state, permission/restore prompts, edit/copy affordances, attachment preview cleanup, thread menus, glyphs, pager/focus/announcements and placement DnD. Keep existing chat-core controller/reducers as their implementation. C1 supplies neutral Markdown/state; C2a/C4 own elements, C2b composes them, C3 owns chrome. A8a/A8b only assemble delivered pieces with domain adapters. Transfers are bounded to these approved responsibilities; any newly discovered neutral core API change outside a lot's paths returns to the conductor.

Keep in hosts: API schemas and authentication, workspace/entity lookups, title/document/job SSE policy, context/tool scope, local-tool result retry and executor, checkpoint classification/transport, todo schema/close API, Drive, downloads, extension RPC/config/auth/prompt policies, queue operations, storage keys and external handoff. Root dock offsets stay A0b; the StreamMessage adapter stays A9. Generic UI must accept callbacks/data rather than import `$lib`, `$app`, extension globals or resource endpoints.

Immo compatibility is a contract for C6a and I8, not a convergence decision: keep feature-off default, forced map docking, external trigger suppression, old tabs/header, local 50-turn history, static restored text, alphabetic provider default, text clipboard and its 1.5 s feedback, retry/edit semantics, provider setup UI and absence of comments/steer/stop/feedback/attachments. N/ChatDock and 1.0.1 preserve the basic display/host mode contract; the newer widget adds header/pager/gate options. These options alone do not prove DOM parity: C6a must exercise both host profiles on the packed Vue entries, and I8 replays immo's as-is acceptance before any convergence.
