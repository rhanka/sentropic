Each process creates one `createClusterMeshModules()` registry, passes it to selected loaders and `createGatewayNamespaceModule`, then mounts through `createClusterMeshPlugin`/the existing namespace registry. No second direct `createGatewayRouter` mount or dispatcher exists. Standalone means independent of the product API and remote control plane, while composing cluster-mesh locally. Disabled/missing/incompatible required modules fail before listener startup. Initial deployment adds no public ingress or enrollment routes. Kubernetes namespaces (`sentropic`, `sentropic-preprod`) are unrelated to HTTP namespaces.

For every tenant, partition verified identities into disjoint sets: product identities use `/gw` mounted in the API; explicitly externally-bound identities use the standalone Service. Key membership by verified credential family/issuer/resource/principal and tenant, using trusted server configuration and D4 directory resolution. Both hosts reject identities assigned to the other path before account acquisition or reservation; absent, ambiguous or overlapping assignments fail closed. A principal cannot gain a second route by supplying a header or switching token aliases. Test the same tenant with one identity in each set, wrong-host attempts, overlap and rollback.

The **trusted server configuration revision is the sole partition authority**: it contains the per-tenant assignments, revision id and content hash, with its previous revision retained for rollback. Both hosts load and verify that configuration before admission; missing or mismatched revision/hash fails closed. `shadowComparison` is evidence, never configuration or authorization authority.

Reuse `control.cutovers` (backed by `control.cluster_mesh_namespace_cutovers`), keyed by `(compositionRoot, namespace)`, solely for existing dispatch authority and linked evidence. Both workload bindings refer to `compositionRoot: 'product'`, `namespace: '/gw'`; each process has its own loader registry. The current enum admits only `product|auth-idp`; no `standalone` row or migration. For partition configuration, the row keeps **only the revision id and hash** in `shadowComparison` evidence and the prior id/hash in `rollbackCheckpoint`, never the assignments. Existing dispatch generation/active-author fields retain their original purpose. A partition change can **NEVER advance the product dispatch generation**, change its active author or activate product dispatch; neither host writes cutovers during boot/admission.

Any later transfer between sets follows the control-plane D11 fence/drain/rollback discipline: compare read-only intent, fence/drain the old assignment, activate the trusted partition configuration revision once, prove rollback and remove the replaced assignment. A product dispatch-generation cutover is a separate operation and scope. Never mirror inference or let both paths debit. Existing public paths remain; any later forwarding adapter preserves DPoP's externally signed URL through a verified delegation contract.

## 3. D3 — Boot, readiness, and shutdown (reversible)

Production configuration is validated once: `NODE_ENV=production`, `PORT=3001`, `HOST=0.0.0.0`, database/issuer/audience/scope configuration, identity store, pricing strategy, mesh account store, and runtime secret-key delivery. Non-secret policy is versioned configuration; secrets are references/files or explicit secret-backed variables. Startup rejects unknown mode, empty key, ambiguous identity configuration, missing required adapter, or stub/noop production wiring. Cross-user pool remains disabled for this own-seat rollout.

Acquire mesh/gateway/auth capabilities through the shared cluster-mesh registry, construct the planner over owner-scoped storage, and inject real `callerAuth`, `routePlanner`, `routeMetering`, admission and readiness into the gateway namespace module. It alone invokes the owner router factory. `GatewayConfig` still contains legacy pool/auth/dispatch fields: the build must either supply concrete compatible ports or add a typed routed-host configuration that excludes unused ports. Spreading `stubGatewayConfig` is not an acceptable production completion criterion. No local-file/in-memory fallback when Postgres is unavailable; no migrations from the serving process.

| Probe/lifecycle | Required behavior |
|---|---|
| `GET /healthz` | 200 while the listener/event loop is alive; no remote dependency call or credential details. |
| `GET /readyz` | 200 only after configuration, expected schema version, database query, identity/verifier readiness, runtime decryption self-check, ledger/pricing, and mesh inventory initialization succeed; otherwise 503. Probe must be explicitly injected. |
| Dependency degradation | Bound checks to 2 seconds, cache readiness for at most 5 seconds; request admission still validates dependencies. Unknown signing key with unavailable JWKS fails closed; a still-valid cached key may verify. No live generation or token refresh in probes. |
| Pool readiness | Initial inventory must expose at least one executable configured route. Afterwards, individual tenant exhaustion/expiry remains a request-level refusal; do not drain all tenants for one caller's cap. Global absence of executable routes makes readiness 503. |
| Shutdown | SIGTERM marks not-ready immediately, stops new admission, drains active streams up to 25 seconds, aborts remaining provider work, persists settlement/reconciliation, then closes HTTP/DB. Pod grace period 40 seconds. |

Expose only coarse probe responses; detailed failure reasons go to restricted, redacted telemetry. Log request/correlation references and outcome, never prompts, authorization headers, seat ids, refresh material or reversible account fingerprints. Export request refusals, estimated settlements, pending reconciliation, seat degradation, metered-fallback count, and drain failures through the existing telemetry sink; building alert delivery is a required dependency, not an assumed installed stack.

## 5. D5 — Real budget admission and HTTP 429 (G1a irreversible, owner-ratified)

The **gateway emits** `GatewayError('over-budget', ..., retryAfterSeconds)` from a new admission stage; `router/errors.ts` produces the existing Anthropic/OpenAI 429 body plus `Retry-After`. It is a local quota refusal, distinct from the already implemented upstream-provider 429. Mesh never emits financial quota HTTP errors. Neither `control.cost_ledger` observation hooks nor cluster capacity counters are admission authorities.

The application-owned adapter implements BR-47 reserve/settle/refund against `control.budgets`, immutable `control.model_pricing`, `control.tenant_budget_strategy`, durable reservation holds and `control.blocked_attempts`, with **one row per gateway request reaching settlement in the existing `control.cost_ledger`**. G1a is the **IRREVERSIBLE, owner-gated budget migration, ratified now by O-D2 (2026-09-24)** and required for this lot's real 429 emitter; it excludes identity bindings. These tables/constraints and ledger extension remain TARGET until implementation. Preserve the deployed `generate|stream` enum and historical nullable records; add principal/strategy/pricing/result/reconciliation attribution without rewriting historical cost as zero. Reconcile BR-47's conceptual operation names within this additive migration.

1. Verify identity via D4, check D2 partition and resolve the tenant's strategy; validate request size/model/wire and a finite output ceiling. Anonymous mode stays off in v0; missing strategy or price refuses dispatch. BYOK exemption applies only to platform-funded caps, not configured caller/workspace limits or attribution.
2. Obtain **side-effect-free candidate and usage bounds** through the mesh quote seam specified in B0/B3a: all permitted fallback models, bounded attempt count and finite input/output/reasoning/image/tool allowances from catalog/policy, without acquiring any account. The application adapter attaches BR-47 prices and funding classes to compute liability; mesh never reads financial pricing/budget tables. Do not duplicate the equivalence council in the host. Reserve the conservative total possible liability, including billable failed attempts. Pin quote/policy/pricing versions so execution cannot introduce an unreserved candidate or larger ceiling.
3. In one short Postgres transaction, lock all applicable tenant/workspace/principal/per-model funding buckets in deterministic order; require `spent + reserved + liability <= cap` for every finite cap. Missing required bucket is a configuration refusal. Atomically create a unique hold and increment all reserves, or roll back everything. Preserve explicit tenant/workspace columns and tenant-qualified uniqueness; never use an unqualified cross-tenant `scope_key`.
4. A cap rejection writes one `blocked_attempts` audit event with no cost row and no account acquisition/dispatch. Raise `over-budget` **outside the provider retry/classification loop**. Bound the hint to `Retry-After = min(60, max(1, ceil((resetAtMs - nowMs) / 1000)))` seconds using the latest blocking reset/hold deadline; monthly caps must not emit a 30-day delay. The 60-second default is reversible and does not promise funding. Pricing/store failure returns sanitized 503, never false 429 or a free request.
5. After reservation, plan and execute through mesh. Release the hold if no attempt was dispatched. For each dispatched attempt preserve normalized usage and the quoted model's price version; absent usage must become a conservative nonzero estimate unless no billable dispatch occurred. Current `routeUsage()` returns estimated zeros when usage is missing: the production adapter must resolve that gap, not silently accept zero liability.
6. On success, error, cancellation or shutdown, settle **one aggregate request** across all attempts: debit actual/estimated micro-USD unconditionally, release the original hold, write the ledger row and settlement outbox event atomically. No cap predicate on settlement; an underestimated actual cost is still charged and prevents later admission. Keep per-attempt price/usage detail in a redacted breakdown, without opaque plan refs/account ids. Do not price mixed-provider attempts as one final model.
7. Database idempotency fences settlement by server request/hold id, not an in-memory flag. Exactly one `control.cost_ledger` row represents each gateway request reaching settlement, including zero-usage outcomes; retries, observation and redelivery cannot add a second row. The standalone host **does not wire `recordLlmUsage`**; mesh `onResponse` is telemetry-only. The composed gateway follows the same rule, or if observation is retained it must upsert using the identical settlement idempotency key. Non-gateway API observation keeps its sink. Pre-admission auth/validation refusals have no financial row; cap refusals use `blocked_attempts` only. Keep settlement exceptions outside provider-fallback catches so DB failure after generation never repeats dispatch.

Wire-contract decision F7: preserve the frozen error snapshot. OpenAI SDKs retry `rate_limit_exceeded`, but not `insufficient_quota`; bounded `Retry-After` alone does not make terminal quota errors retryable. If desired SDK behavior requires changing that mapping, open a separate owner wire-contract decision with snapshot/SDK evidence before implementation; no mapping change or new pending irreversible decision is introduced in Lot D.

Crash handling is part of admission: durable holds have a deadline, dispatch-start marker and fenced ownership. A reaper refunds only proven never-dispatched work; an expired potentially dispatched hold converts to conservative estimated spend plus a reconciliation record, rather than freeing liability and permitting overspend. Late settlement/reaper races use the same idempotency fence and auditable corrections. No DB transaction is held during streaming. If the ledger fails after bytes are sent, terminate/record the stream failure without trying to replace HTTP status with 429; leave recoverable durable liability and make readiness fail until settlement storage recovers.

Per-tenant financial strategy and funding remain BR-47 decisions. This spec does not approve new cross-principal pooling, introduce billing, or turn a flat-price seat into an unmetered bypass. Seat operational quota/cooldown and financial workspace caps are separate; metered-key fallback must reserve its own liability before dispatch.

The scheduled GitHub Actions job is the **SOLE refresher** of custody-managed seats. After provider refresh it updates the GitHub Secret by API **and itself pushes** the fresh access token into `sentropic-llm-seats`. Serialize refresh per device; fence publication by CAS on the Secret's `generation`, using Kubernetes `resourceVersion` to reject concurrent updates. Reject older generations; retry interrupted delivery of the same fresh result without another token rotation. The custody lane owns this Node/TypeScript job, bounded retries and redacted failure alerts. Image publication/rollout never refreshes seats; the serving process has no GitHub credential or Kubernetes Secret API permissions.

O-D3 selects **PREPROD FIRST**: the job uses existing `KUBE_CONFIG_DATA_PREPROD`, confined to `sentropic-preprod`. O-D1 maintains this delivery with full knowledge of its new CI→cluster Secret-write boundary. **Production seat delivery is deferred and owner-gated** until the IP-change spike passes and the refresh/delivery loop is stable. A production write credential would be a **NEW SECURITY GATE**, departing from the current main/preprod-only boundary; design no prod Role or credential now. Neither shared-image promotion nor a main merge activates production seat delivery.

Proposed projection JSON: `schemaVersion: 1`, monotonic `generation`, `generatedAt`, and `seats` entries containing `seatId`, provider device reference, `providerId`, `ownerScopeRef`, `status`, `refreshCount`, `refreshedAt`, `tokenExpiresAt`, and `credential {accessToken, expiresAt, providerExtras}`. No Git commit revision is a secret-version authority. The projection excludes refresh tokens; only explicitly allowlisted provider extras reach the mesh transport. Treat all credential fields as secret-class data and never log device/account references or payloads.

Choose custody §4.1(b): a **resolver reads the Kubernetes Secret projection in `custody-managed` mode**, supplying access material only inside the mesh credential boundary. Verify the immutable DB owner claim **once at resolver initialization/enrollment**, using D4's plain `ownerScopeRef`↔`owner_user_id` mapping; missing, ambiguous or conflicting claims refuse eligibility. New seats/mappings require that verification before admission. Persist only existing non-secret ownership/account metadata. **No second persistent copy of custody access tokens in Postgres**, encrypted or otherwise: those copies would enter pgbackup dumps on S3. No hydration into encrypted account rows or fallback to a stale DB token.

Read a complete validated snapshot at boot; watch/re-read the projected directory with bounded polling, never `subPath`. Install snapshots atomically; reject unknown schema, generation rollback, invalid expiry or owner reassignment. Refresh memory on generation changes without image rollout; removed/revoked seats lose local eligibility. Gate every acquisition on status, expiry and freshness with a safety margin, and fail closed/alert on unreadable or stale projection. Kubernetes propagation is asynchronous; the target ~30-minute cadence against ~1-hour expiry must be measured per provider.

Runtime **never refreshes custody-managed seats**, including the stale spec's optional ephemeral refresh. Ordinary non-custody accounts retain mesh-coordinated refresh. Metered fallback requires explicit configuration, matching owner/workspace authorization and reserved budget; otherwise return provider-shaped unavailability. Emit `reauth_required`, freshness/refresh failure and metered-fallback alerts, without token material.

Revocation is **PER DEVICE at the provider**. Deleting a GitHub Secret or projection only withdraws local availability and does **not** revoke provider credentials. The custody operator performs provider device revocation, then marks/removes the local projection and confirms the revoked device cannot call/refresh while unaffected devices remain usable. Require an audit trail, named operator and measured drill/SLA; known-revoked material is never restored by rollback. O-D1 inherits custody/provider-terms acceptance; no legal reapproval gate is added.

Postgres backup/restore retains ledger and ownership metadata, with existing non-custody encryption-key recovery separate. Assert custody access/refresh tokens are absent from DB rows and pgbackup dumps; GitHub Secrets and the job own custody recovery. Residual risk F11: `deploy/k8s/base/70-pgbackup-cronjob.yaml` uses `amazon/aws-cli:2.34.53`, a Python-based runtime forbidden by the owner's no-Python rule. This existing backup dependency is outside Lot D's scope; flag it for the backup owner, without changing it or adding a new backup runtime.
