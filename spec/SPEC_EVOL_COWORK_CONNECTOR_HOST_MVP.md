## 1. Current-state grounding

- Connector host requires an adapter plus `secret`, `account`, `tenantWorkspace`, and redacted `audit` ports (`packages/connector-host/src/ports.ts:3-69`); a request carries authenticated principal, optional workspace, connector/capability, input, and advisory hints (`packages/connector-host/src/mount.ts:18-44`).
- The mount rejects principal-bearing hints, lets capability hints narrow only, refuses resolver principal mismatch or adapter tenant broadening, intersects workspace exposure/policy/manifest visibility, then invokes the adapter (`packages/connector-host/src/mount.ts:84-109,181-286`). Its current context derives request/correlation ids from enrollment and does not forward hints into `invokeTool` (`packages/connector-host/src/mount.ts:112-178,260-271`); per-call lease idempotency therefore needs trusted handler context, not a hint. Tests prove deny-as-missing, no secret leakage, narrowing, and tenancy guards (`packages/connector-host/tests/mount.test.ts:247-357`).
- The common adapter manifest already classifies scope, redaction, mutability, external mutation, idempotency, human/principal/policy gates, and tenant resolution (`packages/mcp-platform/src/manifest.ts:17-80,112-169`); its runtime context keeps verified principal/tenant/workspace separate from hints and exposes audited JIT secrets (`packages/mcp-platform/src/runtime.ts:202-267`).
- #439’s rule is per-request, token-derived principal/tenant, advisory hints, enrollment/consent and fail-closed denial (`packages/mcp-platform/src/authz.ts:4-13,98-138,152-215`). #492 requires capture before destructive transaction, durable tombstone inside it, and revocation after commit (`api/src/services/connector-grant-teardown.ts:1-38,81-116,143-222`; call-site ordering at `api/src/routes/api/me.ts:216-224,299-311`).
- Cowork currently exports exactly `screen_capture` and `input_action`; the registry runs consent before the executors (`packages/cowork-desktop/src/tools/registry.ts:12-21,23-94`). Windows capture uses `screenshot-desktop`; input uses nut.js click/type/scroll/key (`packages/cowork-desktop/src/capability/windows-provider.ts:9-19,103-169`), but capture still returns the whole screen with zero dimensions (`packages/cowork-desktop/src/capability/windows-provider.ts:106-120`).
- Enrollment, API URL, and storage exist: the binary has device-code auth (`packages/cowork-desktop/src/enroll/device-code-client.ts:4-14,72-193`), a baked API base with override (`packages/cowork-desktop/src/config/api-base-url.ts:14-27`), and file-backed refresh/user plus memory-only access token (`packages/cowork-desktop/src/storage/file-store.ts:15-26,43-58,76-95`). The bridge already has refresh-on-skew (`packages/cowork-bridge/src/auth/session-auth.ts:124-198`), but the CLI does not use it and re-enrolls after restart (`packages/cowork-desktop/src/cli/run.ts:77-101`).
- The runner can parse a status, gate, execute, and post (`packages/cowork-desktop/src/runner/cowork-runner.ts:8-17,39-79`), but the CLI constructs it without an SSE consumer or prompt and then waits (`packages/cowork-desktop/src/cli/run.ts:103-127`). Its poster sends a batch (`packages/cowork-desktop/src/runner/tool-results.ts:19-47`) while chat-server accepts one canonical `{toolCallId,result}` (`packages/chat-server/src/index.ts:857-914`). The benchmark therefore calls 0.2.0 a primitive/distribution prototype, not a functional loop (`spec/SPEC_STUDY_COWORK_COMPUTER_USE_BENCHMARK.md:100-119`).
- No Cowork webview exists; BR-41b remains an unchecked plan (`PLAN.md:311-318`; `plan/41b-BRANCH_feat-cowork-local-webview.md:59-93`). `@sentropic/chat-ui` does provide a host with transport/StreamHub (`packages/chat-ui/src/hosts/createWebHost.ts:66-122`), session transport verbs (`packages/chat-ui/src/client/transport.ts:25-94,188-213`), `SessionList` selection (`packages/chat-ui/src/components/SessionList.svelte:3-16,65-106`), sorted projection and NDJSON hydration (`packages/chat-ui/src/state/sessionList.ts:22-62`; `packages/chat-ui/src/state/chatSessionHydration.ts:1-12,36-94`).

## 2. Connector and mount contract

**PROPOSAL:** register adapter `connectorId='cowork-desktop'`, with no resources/prompts/secrets and two tool capabilities. `screen_capture` is `read-only`, `mutatesExternalSystem:false`, redaction `high`, scope `cowork:screen:capture`, no idempotency requirement, and human/principal/policy gates. `input_action` is `state-transition`, `category:'write'`, `mutatesExternalSystem:true`, redaction `high`, scope `cowork:input:act`, connector-instance idempotency, and elicitation/human/principal/policy gates. Names and schemas remain the existing cross-host vocabulary; no `desktop.observe/act` alias is introduced in this MVP.

| Port / seam | Same-day behavior |
|---|---|
| `tenantWorkspace` | Resolve only from authenticated chat user + selected workspace; return explicit exposure subset of the two capabilities; deny absent workspace grant, stale auth, or mismatch. Model input never establishes tenancy. |
| `account` | Treat the human-selected durable `deviceId` as the connector account; re-resolve ownership, active presence, advertised capability, and workspace exposure; return `connectorInstanceId=enrollmentRef='cowork-device:'+deviceId`, no secret refs. Missing/ambiguous selection denies; never broadcast or auto-pick. |
| `secret` / `audit` | No Cowork capability requests secrets; unexpected access fails. Audit lease/action/consent/result metadata and hashes, never bearer tokens, typed text, or raw screenshots. |
| adapter broker | An adapter-injected `CoworkCapabilityBrokerPort` issues/awaits/revokes leases. It is not added to generic `ConnectorHostPorts`; the adapter calls it from `invokeTool`. |
| chat glue | A context-carrying internal handler maps model tool calls to `driver.invoke({sessionPrincipalSub,requestedWorkspaceRef,connectorId,capabilityRef,input,hints})`; only trusted chat code adds validated `accountSelectorHint`. The handler binds `toolCall.id` to a per-invocation broker/adapter closure (or an architect-approved additive mount field), never to advisory hints. Do not route through `api/src/routes/api/mcp.ts`, whose current surface is a default-off inbound resource server (`api/src/routes/api/mcp.ts:14-26,108-160`). |

#439 applies at every list/invoke/result step: token principal and server workspace are authoritative; target/capability hints only narrow; exposure is connector-account-workspace-capability specific; unauthorized capabilities are absent. #492 applies to future device/account/workspace/user teardown: capture active leases/grants first, tombstone intent atomically with deletion, revoke device leases/credentials only after commit. The demo adds no destructive device-management route; any such route is blocked until it follows that ordering.

## 3. Feature 1 — chat inside Cowork with conversation selection

Add a packaged, local-only Windows WebView2 shell under `packages/cowork-desktop/src/shell/**`; no arbitrary navigation, downloads, new windows, or remote script origin. Its Svelte entry consumes published `@sentropic/chat-ui` CSS/components and composes `SessionList` beside the existing conversation shell. Minimal glue is `CoworkChatHost`: `createWebHost`, projected `fetchSessions()`, selected `sessionId`, NDJSON hydration, send/stop, and StreamHub subscription.

The bearer/refresh token stays in native code. Add a narrow `packages/cowork-bridge/src/desktop-rpc/**` transport: the webview requests chat verbs, native code injects the current bearer, validates route/method/body/response bounds, and proxies named SSE events through the existing `RuntimePortLike` seam. Selection cancels the prior hydration/subscription, fetches history, then subscribes; new session returns/selects its durable session id. The webview never advertises local desktop tools—remote execution is server-side through the mounted connector, preventing accidental execution on the controller machine.

## 4. Feature 2 — Cowork joins a Sentropic chat session

At startup native Cowork calls bridge `SessionAuthClient.getValidAccessToken()`; only absent/invalid refresh state falls back to the existing device-code enrollment. It fetches `/chat/sessions?workspace_id=…`; user selection joins by fetching `/chat/sessions/:id/history` and subscribing to authenticated `/streams/sse`, then sends `/chat/messages` with that `sessionId`. Disconnect/reselect removes only the old stream subscription; the Sentropic server remains the session HOLDER. This controller chat stream is distinct from the target device lease stream in Feature 3.

## 5. Feature 3 — consent-gated remote computer use

Build only the minimum vertical slice from BR-41c: stable device key/id, active device/presence lookup, one target, short-lived one-use lease, device-signed acknowledgement, device-filtered notification plus poll fallback, and atomic consumed/expired/revoked state (`spec/SPEC_EVOL_COWORK_DEVICE_IDENTITY_LEASE.md:405-468,470-531`). One invocation is:

1. The human selects remote Cowork **B** in controller Cowork **A**; the selected durable id never comes from model arguments.
2. Chat’s internal connector handler calls the mount; mount re-resolves #439 tenancy/exposure/account. The broker issues a capability-scoped lease keyed by `toolCall.id`, nonce, target B, and <=45 s expiry.
3. B authenticates with refreshed bearer, receives only its notification/poll row, verifies the envelope, and signs `cowork-lease-ack-v1:${leaseId}.${nonce}`; BR-41c already requires active-device recheck and atomic one-time ack (`spec/SPEC_EVOL_COWORK_DEVICE_IDENTITY_LEASE.md:415-443,454-468`). Architect must confirm whether the lease envelope itself also needs a server signature (OQ-7).
4. B shows a foreground prompt with untrusted model intent, capability, current app/window, screenshot preview or coordinates/text summary, reversibility, and expiry. Only **Deny** or **Allow once** exists for `input_action`; no `allow_always`. The demo policy permits capture plus click/scroll/type only inside an isolated non-admin OVH VM and blocks key chords, Enter/submission, credentials, messaging, purchase, deletion, sharing, upload/download, permission and legal actions.
5. After consent B executes the existing provider, posts one idempotent `{toolCallId,result,deviceId,leaseId,nonce}` record, the broker atomically consumes the lease, and the connector returns. A 30 s timeout, offline target, denial, mismatch, replay, stop, or malformed result revokes/expires and returns **PAS-FAIT**, never success.

This enforces the study’s explicit device lease, two-sided authorization, action-aware consent, no permanent hands, sensitive-action stop, isolated default, egress constraints, device-bound identity, redacted audit/kill switch, and safety tests (`spec/SPEC_STUDY_COWORK_COMPUTER_USE_BENCHMARK.md:179-203`). The local Stop button revokes the active lease, closes delivery, disables further input, and exits; full held-key/button recovery remains hardening, so the MVP permits no long-held input.

## 6. Fusion invariants I1–I5

Found at `origin/feat/d6a-agents-surface-fusion:spec/SPEC_EVOL_AGENTS_SURFACE_FUSION.md:17-25` (the file says the authoritative publisher is h2a governance). Quoted verbatim:

- **I1:** “durable identity crosses the boundary, never a conversation id. Reserve the slot for the reclaimed identity; do not weld an ephemeral id while the resume path is repaired.” Device routing uses durable `deviceId`; `sessionId` only joins chat and never identifies a Cowork connector instance.
- **I2:** “the surface states, operation by operation, what is measured and what is asserted.” Presence (`lastSeenAt`) and capture (`capturedAt`) are measured; stored session history, capability advertisement, and device-reported execution are labelled asserted with source/time.
- **I3:** “every object is marked HOLDER or VIEW. A renderer never persists a VIEW, and the holder wins on disagreement.” Sentropic holds sessions/leases; Cowork B holds device capability/execution facts; Cowork A renders VIEWs and never writes them back. Stale/conflict means unavailable.
- **I4:** “capabilities use the existing cross-host vocabulary. No host-specific second grammar is opened.” The connector manifest exposes only `screen_capture`/`input_action` using `AppCapability` fields.
- **I5:** «un échec ne doit jamais ressembler à un succès ; l'appelant doit pouvoir distinguer FAIT / DÉPOSÉ-EN-ATTENTE / PAS-FAIT ; refuser est le défaut LÀ OÙ accepter honnêtement est impossible.» MVP returns **FAIT** only after signed ack, consent, execution and accepted canonical result; it has no dormant queue claim, so timeouts are **PAS-FAIT**. Durable **DÉPOSÉ-EN-ATTENTE** is deferred until `DurableCallRef`/wake semantics are ratified.

## 7. Exact same-day MVP versus deferred

**Functional demo target TODAY after build:** Cowork A opens embedded chat, lists/selects/creates Sentropic sessions, restores history, sends and streams; refreshed enrollment joins remotely; the human selects a different enrolled Cowork B; the AI captures B and performs separately confirmed low-risk click/scroll/type steps; denial, offline, wrong-device, replay, timeout, and Stop visibly report not-done. Nothing in this design-only commit makes that functional yet.

**Deferred:** BR-41c key rotation, DPAPI, device-management/reaper and full teardown; BR-41d durable dormant/wake, reconnect races, parallel calls and full retry/idempotency; BR-41e task/session grants, complete risk taxonomy/interstitial UX, evidence review and held-input recovery; production isolation policy, prompt-injection/DLP, crop/DPI/accessibility, signed distribution, unattended autonomy, host-machine mode, macOS/Linux, fleet/shared-device control, and any high-risk/irreversible action. There is no production-ready “takeover” claim until those gates pass.
