## 2. Tenant model (frozen)

- Isolation key: every call and object carries a mandatory `tenantId`; sandbox isolation is keyed on `(tenantId, sessionId | jobId)`.
- Warm standby pools are partitioned: `poolOwned = system:warm-pool:<tenantId>`. A cross-tenant claim is rejected (`403` / `409`).
- Canonical hierarchy: `builder.slice/builder-tenant.slice/builder-tenant-<tenantId>.slice/builder-sbx-<physicalUid>.scope`. Parent MemoryMax=2944 MiB, MemoryLow=1408 MiB, MemorySwapMax=512 MiB, CPUQuota=180%; intermediate MemoryLow=1408 MiB. Each tenant: MemoryMax=2304 MiB, MemoryHigh=2304 MiB, MemoryLow=704 MiB, MemorySwapMax=256 MiB, CPUWeight=100, TasksMax=2048. Warm scopes: max/high/low=704 MiB, CPUWeight=200, swap=0. Build scopes: max=1536/high=1408/low=0 MiB, CPUWeight=100, swap<=256 MiB. All scopes: OOMPolicy=kill (memory.oom.group=1); TasksMax and OCI pids.limit=512 for sessions, 1024 for builds (AMD-20/27).
- AMD-17 supersedes AMD-13: MemTotal=4,005,416,960 bytes, floor 3819 MiB. Host 512 + agent 192 + parent 2944 + margin 171 = 3819 MiB. Agent and system.slice MemoryMin=64 MiB. zram nominal 1024 MiB, physical mem_limit=128 MiB inside the margin. Below floor 3819 reduce admission and parent ceiling.
- Disk layout (mode `0700`, tenant-private ext4 loop images with prjquota):
  `/var/lib/builder/tenants/<tenantId>/bases/<kind>/<identityDigest>.erofs` and
  `/var/lib/builder/tenants/<tenantId>/sandboxes/<uid>/{upper,work,retained}`.
- Zero static S3 secret on the VM: control-plane-issued presigned URLs only, bucket `sentropic-execution-bhs`, prefix `tenants/<tenantId>/<env>/`, exact BHS host/bucket/tenant/env validation before I/O. Both tenant access/secret keys stay in sentropic control plane (`SANDBOX_S3_{SENTROPIC,IMMO}_ACCESS_KEY_ID` / `_SECRET_ACCESS_KEY`), k8s mint/90-day rotation.
- AMD-21 AdmissionLedger: one warm live OR standby per tenant (704 MiB each), plus one global publish build (1536 MiB), sum <=2944 MiB. Gate on reservations alone; full tenant memory.current (including destroyed-scope cache) is telemetry. Reject 429 before allocation. Disk/project quota 16 GiB per tenant plus per-sandbox block/inode hard limits required before launch. Claim transfers the standby reservation.
- Publish queue: two outstanding heavy jobs per tenant, active included, quantum 1, strict eligible-head alternation. Only a tenant's eligible head has at most one adverse service ahead; position q waits at most q own and q+1 adverse services. Service limits: artifact-build 60 s, prebundle/cold-materialize 120 s. Stop and destroy before releasing capacity. Live admission alone targets p95 <=2 s/max <=5 s outside the build slot. Queue-full 429 counts as qualification failure.
- AMD-14: one shared warm counter per tenant (live + standby <=1); claim transfers it. Retained stop does not allow replacement; complete destruction purges runtime, scope, mounts and upperdir before releasing the reservation.
- Observability: every audit row and metric carries `tenant_id` (+ `purpose`, `node_instance_id`); all evidence stays in BHS.

## 3. ExecutionNodeV1 identity and transport (frozen)

- `contractVersion`: `execution-node.v1`.
- D6-B decided: inbound mTLS on public IPv4 TCP 8443, nftables MKS-egress/operator allowlist synchronized by k8s, no vRack. Outbound relay is S2-2, routes unchanged.
- mTLS roles: operator/control-plane/data-plane, headers X-Tenant-Id, X-Expected-Physical-Uid, X-Custody-Token. Signed custody tokens include tenantId, principalId, custodyEpoch, resourceId, issuedAt, deadlineAt; TTL <=60 s. Mutations fail closed after >5 s without authenticated control-plane heartbeat.
- `nodeInstanceId`: k8s-owned `/var/lib/builder/node-instance-id`; agent-owned monotone `nodeEpoch` fsynced before listening. A new disk means a new instance id. Unknown instance returns `409 unknown_node_instance`.
- AMD-22: sentropic-api CN `control-plane:sentropic-api` posts `/v1/node/heartbeat` every 1 s, `{expectedNodeInstanceId,expectedNodeEpoch,sentAt}`; no tenantId. Only this authenticated role refreshes custody. GET node accepts operator/control-plane mTLS alone, no ticket; k8s probes every 5 min. No heartbeat push. Probe stdout archives through cluster Fluent Bit to `sentropic-cluster-logs/raw/poc-ca/builder-vm-probe/`.

## 4. Ownership and compatibility (frozen)

- Ownership (every sandbox/claim): `{ tenantId, poolOwned, workspaceId, principalId, sessionId, buildId, jobId, attemptId, purpose, generation, custodyEpoch }`.
- Owner 13/11 devScope: `{kind: ui|api|jobs|data|fullstack,writable[],refused[],source:{repo,path,commit}}`, resolved by the host from the application's own registry, configured per tenant/session, never copied into the agent. Store it on the session and require the same policy on every session mutation; audit provenance. Enforce normalized paths, refused precedence and rejection of symlink/hardlink writes. Sandbox source is read-only; host-mediated `/write` modifies only permitted source. OutputDir `ui/dist` remains separate and excluded from source writes.
- `standbyCompatibility` is immutable per base: `{ tenantId, repoId, sourceTreeSha256, lockSha256, prebundleDigest, rootfsBaseDigest, profile, viteConfigDigest }`. Claim requires exact `tenantId` equality plus full compatibility equality; a pool-owned standby flips `poolOwned` to `false` atomically on claim.
- Execution ticket (`X-Execution-Ticket`, Ed25519): `{ v1, tenantId, commandId, method, path, bodySha256, targetNodeId, expectedNodeInstanceId, expectedNodeEpoch, ownership, issuedAt, deadlineAt }` with `deadlineAt - issuedAt <= 30 s`.
- Idempotence-before-state rule on `(tenantId, commandId)`:
  - replay with the identical triplet (same ticket body hash) -> `200`/`201` with the original result;
  - same `commandId` with a different body -> `409 command_id_payload_mismatch`;
  - distinct `commandId` on an already claimed box -> `409 already_claimed`;
  - obsolete epoch -> `409 stale_node_epoch`.

## 5. Lifecycle (frozen)

- Normative cycle: `creating -> standby | running -> stopping -> stopped-output-retained -> exported -> destroyed` (`failed -> destroyed`).
- Normative D5-M1 build sequence: `BUILD_RECIPE` (`npm --ignore-scripts --offline run build:artifact` on a fresh box) -> `stop { retainOutput: true }` -> `export` -> `DELETE`.
- Internal W3 behavior: claim starts a new frame without restarting vite; `attach`/`applyRevision` apply at L4 onto `/workspace` (gVisor inotify); `put`/`dependencies/install` returns `410 deprecated_on_overlay_node` on the VM.
- Startup inventories tenant scopes, preserved runsc state, sandbox directories and mounts before creating admission counters/listening. Survivors or an inventory error block startup until operator reconciliation; complete adoption remains S1-A1b. Heartbeats cannot bypass the fence.
- Successful exit before the first runsc `running` observation still delivers runtimeId/onExit; confirmed cgroup quiescence is required before export. At quiescence, execution timeout is cancelled while reservations/global build slot stay held. Retention expires from confirmed stop (requested retentionTtlMs=0..300000, default 300000; natural success=300000); exports do not extend it. Runtime destruction precedes capacity release.
- Box network: AMD-28 CO-SIGNED by k8s on 2026-11-13 (commit `3b042fd`): only `live`/`standby` profiles may request `network: ports`, fixed port 5173, using `--network=sandbox --platform=systrap` in a fresh private loopback-only netns. All other profiles (including artifact-build, prebundle, cold-materialize and browser-harness) remain `--network=none`. Unknown network values are refused. Pre-exec checks enforce UP lo alone, only 127.0.0.1/8 and ::1/128, all-table IPv4/IPv6 loopback-only routes (including main-table ::1 dev lo), and a namespace distinct from PID 1. Post-start sentry inode must match the launcher's and differ from host/peers; lo alone and no kernel listeners. Flag/spec audits forbid raw/proxy/XDP (except off)/NAT/nftables/pcap/packet-write/flag-override, dev.gvisor.* annotations and network devices, require empty capabilities and explicit --host-uds=none/--host-fifo=none. Violations destroy the sandbox, audit and return 500 network_isolation_violation. Forwarding uses only --stream=<UDS>, never host TCP forwarding, with a bounded agent-wide helper budget/queue and 429 ports_saturated. k8s owns the closed-by-default EXECUTION_NODE_PORTS_ENABLED and EXECUTION_NODE_PORTS_RUNSC_SHA256 keys in /etc/execution-node/agent.env; only true plus the qualified binary digest enables ports. Closed/mismatched settings remove ports discovery, return 409 ports_disabled, cut streams within 250ms and stop ports sandboxes. Every runsc bump requires requalification. k8s installs util-linux, dash and iproute2; qualification covers both modes/two tenants, TCP/UDP/DNS/metadata/public/host/kernel/peer isolation, raw/packet refusal, unchanged host listeners, fixed-port refusal, bounded bursts, switch/digest failures and stop/failure/OOM/crash cleanup. Receipt identifies archive and runsc SHA-256.

## 6. Endpoints (frozen surface)

- AMD-28 profile mapping: live/standby denote the daemon-derived session slots. The existing `node-22` wire profile remains valid only in those slots, threaded explicitly to the runtime; heavy, browser-harness and unknown profiles cannot select ports.

- OperatorScope: `GET /v1/node` has no tenantId; reports parentSlice `{ name: 'builder.slice', memoryMaxMiB: 2944 }` and capabilities.supportedOps for actually delivered operations. All TenantScope calls require tenantId or 400 missing_tenant_id. QuotaSnapshot contains limits, effective controlGroup, usage.memoryCurrentBytes/reservedMemoryBytes and globalBuildSlot `{ maxConcurrentBuildsGlobal: 1, holderTenantId?, queueDepth }`; no burst fields.
- `GET`/`PUT /v1/tenants/:tenantId/quotas`, `GET /v1/tenants/:tenantId/bases/:baseId` (`kind`: `rootfs | dependencies | source | prebundle | vendor-esm...`; cross-tenant base read -> `403 cross_tenant_base_forbidden`).
- `PUT /v1/tenants/:tenantId/bases`: signed `{commandId,ownership,base:{tenantId,baseId,kind,identityDigest},url}`; stream HTTPS without redirects, verify SHA-256, fsync/publish immutable EROFS and register tenant base. Shared rootfs is sentropic-built and deployed with the agent by k8s; PUT cannot replace it. GET node advertises its digest and `shared-rootfs` baseId.
- `POST /v1/sandboxes` (`SandboxSpec`: mandatory devScope and absolute command argv, `tenantId`, `physicalUid`, `profile`, `runtimeClass`, `baseMounts` read-only, private overlay exposed read-only to the runtime, `quotaMiB` + inodes, process `uid:gid`, `network` (`none` | ports allowlist), `exec`/`pty`/`snapshots` flags). `/start` launches a created record and confirms runsc running state. Every session mutation repeats devScope; `/write` takes path/contentBase64 and a signed command. Ticket verification is bound to executed parameters, command, route, owner and node; a verification key is mandatory for the real adapter.
- `POST /v1/sandboxes/:id/claim`, GET list/detail (scopeName and resources.memoryCurrentBytes/memoryPeakBytes), renew, stop, export and DELETE. Stop resolves systemd ControlGroup and validates tenant ancestry (500 cgroup_tenant_mismatch, no write otherwise); scope-only cgroup.kill and cgroup.events, never tenant kill. Within 5000 ms: 200 stopped-output-retained/destroyed with allProcessesExited:true; otherwise 202 stopping/allProcessesExited:false/retryAfterMs:250. Export requires buildId and confirmed quiescence (409 sandbox_not_quiesced), read-only symlink-safe reader.
- `POST /v1/sandboxes/:physicalUid/revoke-custody { tenantId, physicalUid, minCustodyEpoch, reason }`: minCustodyEpoch=max(persisted,received), fsync before 200 `{ activeCustodyEpoch, closedStreams, ackedAt }`; close lower-epoch streams with WS 1008/TCP RST locally <=250 ms, end-to-end <=1 s. Refuse new revoked connections/invocations with 403 custody_revoked, including isolates. Epoch 2 then late epoch 1 must remain 2 across restart.
- `GET /v1/events`: exclusive TenantScope tenantId/afterSeq OR operator certificate `?scope=node` infrastructure events only. Delivered node drain/undrain/status POST routes require k8s-signed X-Operator-Ticket compact EdDSA JWS, op/nodeInstanceId/nodeEpoch/iat/exp/jti/aud, TTL<=60 s, aud=execution-node, replay cache. Tenant drain/events remain S1b.
- S2 isolates: one dedicated runsc --network=none sandbox and one dedicated workerd host per session, no intra-tenant host sharing by default. Shared-host benchmarks never qualify strict isolation.
- Data-plane: `ANY /v1/ports/:port/*`, `POST /v1/exec` (S2 cli-remote / agent-loop), `WS /v1/pty` (relay), `POST /v1/snapshots` (`tar.zst` -> tenant-scoped S3), `POST /v1/isolates/:id/invoke` (no egress; upload outside the isolate).
