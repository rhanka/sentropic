# Feature: auth-ui native Design System components (auth.sent-tech.ca)

## Objective
Make `@sentropic/auth-ui` render its 6 screens with **native `@sentropic/design-system-svelte` components** (Button, Input, Alert, Typography, Link, Card) themed by the **`entropic`** theme via `ThemeProvider`, so `auth.sent-tech.ca` (apps/auth-idp/web) and the product `ui/` /auth screens stop rendering the hardcoded indigo `#4f46e5` and use the DS primary. Packaging: DS declared as **peerDependency** of auth-ui; each host provides the DS + ThemeProvider + entropic theme.

## Feedback Loop
- FL-1 `risk`: DS `@sentropic/design-system-svelte` exports a single `.` barrel → verify tree-shaking keeps the auth bundle lean (no Highcharts/chart bloat). Mitigation: measure `apps/auth-idp/web/build` size before/after; if bloated, import via deep paths or raise with DS lane. Status: open.
- FL-2 `resolved`: `@sentropic/design-system-svelte` package.json has ONLY a `.` export — NO `styles.css`. Svelte components ship plain scoped `<style>` (compiled natively) and `ThemeProvider` injects the theme token CSS via `{@html "<style>${compileTheme(...)}</style>"}` into `<svelte:head>`. So NO base-styles import is required at any host; just wrap content in `<ThemeProvider theme={entropicTheme}>`. (The docs app's `@sentropic/design-system-react/styles.css` import only styles React/Vue islands — irrelevant for a Svelte-only host.) Build caveat: a host with a `postcss.config` (tailwind+autoprefixer) + `vitePreprocess()` re-runs PostCSS over DS node_modules `<style>` and ThemeProvider's `{@html}` literal → `Unknown word css`. Fix: `vitePreprocess({ style: false })` on hosts that have a PostCSS config and no `<style lang>` blocks in their own `.svelte` (applies to idp-web). Status: resolved.
- FL-3 `resolved`: host login pages passed slot links with hardcoded colors (`apps/auth-idp/web` `text-primary`, `ui/` `text-indigo-600`) → replaced both with DS `<Link href=... variant="standalone">`. Status: resolved.
- FL-4 `resolved`: first PR #316 CI was red on 3 jobs (all green on base main 6cf87787 → branch regressions): (a) `typecheck-idp-web` — `+layout.svelte` `onLocaleChange={(next)=>setLocale(next)}` → "Parameter 'next' implicitly has an 'any' type" → fixed by passing `setLocale` directly (its `(next: IdpLocale)` matches `onLocaleChange?: (locale:"fr"|"en")`); (b) `build-ui` — same DS-ThemeProvider PostCSS "Unknown word css" the idp host hit → ui/ needed `vitePreprocess({ style:false })` + `resolve.dedupe` (DS peers) [EX1]; (c) `typecheck-lint-ui` — exit 137 OOM-kill (no ui container mem_limit → host-RAM bound; the DS type surface tipped svelte-check over) → capped V8 via `NODE_OPTIONS=--max-old-space-size=4096` in ui/'s `check` script so it GCs under the host limit. Status: resolved (pending CI re-confirm).
- **BR-EX1** (scope exception): touched `ui/svelte.config.js` + `ui/vite.config.ts` (outside declared Allowed Paths). Reason: wiring `ui/` as a DS host intrinsically requires its Svelte/Vite build config (PostCSS `style:false` + DS-peer `dedupe`), mirroring the already-allowed `apps/auth-idp/web` config. Impact: build-time only, no runtime/app-logic change. Rollback: revert the 2 files (auth screens would fail to build until reverted together with the DS wiring).
