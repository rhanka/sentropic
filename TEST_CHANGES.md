# Execution-policy changes

Changes to which tests run and how their failures propagate. None changes a test assertion, timeout, retry count or skip.

| Location | Change | Coverage effect | Failure-propagation effect |
|---|---|---|---|
| `Makefile` `E2E_GROUPS` default | `00 01 02 03 04 05 06 07` becomes `00 … 10`. | Default `make test-e2e` now runs groups 08, 09 and 10 (previously unselected locally). | None by itself. |
| `Makefile` `test-e2e` grouped loop | Pattern `tests/<g>-.*.spec.ts` becomes the anchored regex `tests/<g>[-_].*\.spec\.ts$`; each group exit code is captured, `Playwright invocation summary: <g>: exit <n>` is printed, and the step exits 1 if any group failed. | Selects underscore-named specs (`07_comment_assistant.spec.ts`); all 55 numbered root specs match. | Before: the shell loop returned only the last group's exit code, so an earlier failing group was masked by a later passing group. After: any failing group fails the step; later successes cannot reset it. Scoped `E2E_SPEC` runs keep their own exit code. |
| `.github/workflows/ci.yml` chat-ui job | New blocking step `make test-chat-ui-dom`. | Runs the 204 chat-ui DOM tests previously never executed in CI. | A DOM test failure now fails the job. |
| `.github/workflows/ci.yml` `test-e2e` matrix | group-d `08` becomes `08 09`; group-a `00 02 06` becomes `00 02 06 10`; `billing_dependent` removed. | Groups 09 (five specs) and 10 (`10-cluster-mesh-control-plane.spec.ts`) now run in CI. Spec 10 keeps its own gating unchanged: without the `CLUSTER_MESH_*` qualification variables it executes the source-gap/fence assertions (health generation, 401 `unverified_invocation_context`, module/catalog/streams checks) and its final LOST test keeps its existing `test.skip(!qualificationAvailable)`. | — |
| `.github/workflows/ci.yml` `test-e2e` execution step | `continue-on-error: ${{ matrix.billing_dependent }}` removed; `make test-e2e ENV=e2e-ci`. | Explicit isolated compose project. | Before: failures in groups b, c and d (01, 04, 03, 08) were reported green. After: every lane failure fails CI. |
| `.github/workflows/ci.yml` `test-e2e` diagnostics | New `if: failure()` step `make logs-api ENV=e2e-ci`. | Diagnostics only; no test executed. | Runs only after a failure; does not change the job result. |
| `.github/workflows/ci.yml` `e2e-vscode` | Unconditional `continue-on-error: true` removed; `make test-e2e-vscode ENV=e2e-vscode-ci`. | Explicit isolated compose project. | Before: VSCode E2E failures never failed CI. After: they do. |
| `Makefile` `check-e2e-inventory` + `e2e/scripts/check-spec-lanes.sh`, CI `changes` job step (BR600-EX7) | New shell check: every `e2e/tests/[0-9][0-9][-_]*.spec.ts` group must be in the default `E2E_GROUPS` and in at least one CI `e2e_groups` lane. Runs in the always-executed `changes` job. | Verified locally: 55/55 selected; overriding `E2E_GROUPS` without `10` fails with the spec named. | A new numbered spec (or group) without a lane fails CI before any E2E run. |
