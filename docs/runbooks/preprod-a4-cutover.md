# Preprod A4 cutover — owner review and execution

This is option B of the 2026-11-06 API incident. Building this procedure does not authorize executing it. The owner approves the concrete candidate, fence plan, rollback limits and prior qualification before any Kubernetes change. Actual fence and backup evidence is obtained afterwards and gates preparation/checkpoint. Main deployment remains frozen until that approval and the completed cutover. This wagon has no PR and joins the next dated train; integration owns its final independent review and CI. G7 stays suspended and dry-run throughout this procedure.

## Operator inputs and custody

Use a protected tenant kubeconfig file supplied through the existing credential custodian (`K8S_TENANT_ADMIN_KUBECONFIG_B64` in the central ignored `.env`, by name only). `A4_KUBECONFIG_FILE` is an existing absolute 0600 file, not a credential value. Never enable shell tracing or forward raw kubectl, database, S3, or application errors. All targets below print digests only. Their failure digests indicate refusal; retain private evidence and inspect it inside tenant custody.

Before fencing, the operator creates an absolute 0600 `A4_AUTHORIZATION_FILE` containing only prior approval inputs: `format: preprod-a4-authorization/1`, `namespace: sentropic-preprod`, `operationId`, `authorizationRef`, `candidateCommit`, `candidateImage`. The reference must resolve to the owner's actual approval of the immutable annex. `fence` reads this file and checks the annex digest plus operation/authorization/candidate/image binding; it never reads `A4_REQUEST_FILE` or demands stopped-writer, snapshot or backup attestations. A successful command is not evidence that every writer has stopped.

After the real fence and remote export, the operator creates a separate absolute 0600 `A4_REQUEST_FILE` with these exact fields. Resolve every reference to an existing approved record or actual post-fence receipt; no placeholder, generic CI receipt, or guessed qualification is accepted. Its operation/authorization/candidate/image must match the prior authorization and unchanged annex. `candidateCommit` is the full 40-character train candidate SHA; `candidateImage` is its matching immutable `rg.fr-par.scw.cloud/nc-reg/sentropic-api@sha256:…` release image. Keep their release provenance with the authorization. Preparation, custody and later actions retain the strict post-fence request checks.

| Field | Required content |
| --- | --- |
| `format`, `namespace`, `operationId` | `preprod-a4-request/1`, `sentropic-preprod`, a unique lowercase operation name (at most 40 characters) |
| `candidateCommit`, `candidateImage` | Exact reviewed train candidate and matching image digest; no zero SHA or tag |
| `backupTemplateSha256` | Digest returned by the read-only `inspect` invocation below, ratified by the tenant backup operator |
| `authorizationRef`, `writerFenceRef` | Same prior owner execution approval; actual post-fence receipt covering the enumerated Kubernetes/SQL/file writers |
| `rollbackCheckpointRef`, `rollbackLimitsRef` | Named recovery point and approved whole-database restoration limits, key availability and post-cutover write disposition |
| `sourceMetadataDispositionRef` | Approved retention/access/deletion rules for the full SQL dump and remote snapshot |
| `remoteSnapshotRef`, `remoteSnapshotDigest` | Actual protected remote-session exporter receipt and SHA-256 of its exact UTF-8 JSON bytes |
| `legacyWritersStopped`, `remoteFileWriterStopped` | Literal `true`, backed by the real fence; never predictions |

`A4_REMOTE_FILE` is the actual 0600 remote snapshot, using `remote-session-projection-snapshot/1`. Do not synthesize an empty snapshot. If the real export is empty, its exporter receipt must establish that census. The supplied bytes are checked by the shipped parser and reconciled with SQL sessions. The source snapshot is a full tenant `pg_dump` gzip, preserving historical metadata for D11; no identity row or receipt payload is printed.

`A4_BUDGETS_FILE` is the tenant-qualified 0600 JSON, with its actual `qualificationReceiptRef` and exactly `reservation`, `deletion`, `diagnostic`, `read`, `workspace`, `replicaExport`, `replicaValidation`, `replicaSync`. Each entry has exactly `deadlineMs` (integer 1–600000) and `maxAttempts` (1–3). Obtain values from qualification; the repo supplies no invented budgets.

## Ordered execution after owner authorization

Use the reviewed train checkout. Set only absolute private-file paths in the target arguments; `ENV=test-preprod-a4` is last. These operator targets contact the explicitly supplied preprod kubeconfig; the ENV name isolates local tooling and is not a deployment selector. `A4_DRY_RUN=1` is the default and never creates resources or files.

1. **Before the fence window**, establish a genuine isolated-restored-copy D11 qualification for the exact shipped candidate, mapping/assets and real verifier/source/remote conditions. Review applicability against the preprod census. Reuse an existing receipt only when that coverage is demonstrated and accepted; no such current-candidate proof was found during this build/review. Otherwise the tenant must perform one separately authorized isolated restore and candidate import/D11/auth rehearsal before proceeding. Boot requires a nonempty rehearsal receipt reference; it does not require restoring each final rollback dump. CI success, B03 restore-only proof and G7 dry-run are insufficient. Record candidate/image provenance and the nominated fresh-auth flow, then obtain authorization for the immutable execution annex below. Stop CD/GitOps and external/manual SQL/file writers; record original controller states privately.
2. Run annex action `fence` with `A4_AUTHORIZATION_FILE=/private/authorization.json`, first dry-run then `A4_DRY_RUN=0`, using the exact make invocation below. It quiesces **all Deployments** in `sentropic-preprod`, including API, auth-idp, UI and workers, every non-Postgres StatefulSet, and suspends all CronJobs including `pgbackup` and G7. The fence requires no DaemonSet in this namespace; abort for tenant review if one exists. Wait for running Jobs to finish under the approved fence and for old/terminating writer Pods to disappear. PostgreSQL stays available. Stop the actual remote-file writer outside this namespace too; preserve its export and actual fence receipt. Enforce PostgreSQL access exclusion for external/manual writers through tenant controls. Scaling workloads alone does not fence such writers. Record observed completion in the tenant receipt chain; do not assert success in the prior authorization.
3. Inspect the tenant backup template, review its digest with the backup operator, and create the post-fence request from actual observed Kubernetes/external/remote fence evidence and the real remote export. Set stopped-writer booleans only after those observations; missing/incomplete evidence blocks preparation. Keep the authorization file and signed annex unchanged:

   `make k8s-preprod-a4-prepare A4_PHASE=inspect A4_KUBECONFIG_FILE=/private/tenant-kubeconfig ENV=test-preprod-a4`

4. Validate and create the qualified budgets Secret with `make k8s-preprod-a4-custody A4_OPERATION=budgets A4_DRY_RUN=0 A4_KUBECONFIG_FILE=/private/tenant-kubeconfig A4_REQUEST_FILE=/private/request.json A4_BUDGETS_FILE=/private/budgets.json ENV=test-preprod-a4`. Run it first with `A4_DRY_RUN=1`. No existing Secret is overwritten.
5. Stage only the required overlay changes while API replicas and observed replicas are zero:

   `make k8s-preprod-a4-custody A4_OPERATION=wire A4_DRY_RUN=0 A4_KUBECONFIG_FILE=/private/tenant-kubeconfig A4_REQUEST_FILE=/private/request.json ENV=test-preprod-a4`

   First use `A4_DRY_RUN=1`. This creates the PVC/runtime ConfigMap and patches API and IdP config/deployments/images without changing replica counts. Both consumers must have zero desired and observed replicas. The A4 patches live in `deploy/k8s/overlays/preprod-a4`, whose render previews the wired runtime. Continuous deployment uses `overlays/preprod`, which retains recovery images API `f2313a` and UI `434fe5` and the recovery entrypoints. Remove its temporary image block at the A4 preprod cutover execution, and promote the reviewed A4 runtime configuration before resuming CD. Do not invoke the general preprod deployment target during the fence: applying the whole overlay can reset replicas and release image pins.
6. Create the migration-free custodian with the same command using `A4_OPERATION=custodian`; then stage inputs using `A4_OPERATION=stage A4_STAGE=inputs A4_REMOTE_FILE=/private/remote.json`. Run each with dry-run first, then explicit `A4_DRY_RUN=0`. Staging is exclusive and never overwrites files.
7. Run snapshot preflight, then take the tenant backup:

   `make k8s-preprod-a4-prepare A4_PHASE=snapshot A4_DRY_RUN=0 A4_KUBECONFIG_FILE=/private/tenant-kubeconfig A4_REQUEST_FILE=/private/request.json ENV=test-preprod-a4`

   First use `A4_DRY_RUN=1`. The real invocation checks the fence, reads journals/schema/source in a read-only transaction, clones the approved CronJob template, waits, downloads the resulting `pg/<timestamp>.sql.gz` through the tenant backup identity, validates length/gzip/pg_dump envelope, and saves a private 0600 copy. It rechecks source/schema/journals before writing `snapshot.json`. No checkpoint or application migration is written at this stage. A snapshot preflight cannot validate a future backup; full checkpoint dry-run below validates all existing artifacts.
8. **Rollback point established, before any legacy-table deletion:** the tenant validates and retains the fresh final backup and actual remote snapshot under its backup/retention policy. Review the existing isolated qualification against the fresh census. No second restore of this final dump is mandatory. If meaningful candidate, source, schema, journal, remote or verifier/mapping drift is found, stop and obtain fresh isolated qualification; do not relabel old evidence. The tenant may separately choose the stronger final-dump rehearsal.
9. Stage the accepted private `rehearsal.json`, using the strict `preprod-a4-rehearsal/2` schema: genuine `receiptRef`, `isolatedRestoreRef`, `restoredBackupSha256` of the backup actually rehearsed, `applicabilityReviewRef`, exact `candidateCommit`/`candidateImage`, the seven census hashes (`sourceContentSha256`, `schemaSha256`, `journalSha256`, `remoteSnapshotDigest`, `mappingSha256`, `identityAssetSha256`, `connectorAssetSha256`), and literal `candidateBootPassed`, `functionalAuthPassed`, `d11Passed: true`. Qualification must cover both product and IdP verifier/auth behavior. The mapping hash binds the product verifier used for import; the applicability review records the IdP verifier separately. These logical hashes must match final inspection; the rehearsed dump hash need not equal the final rollback dump hash. Operation IDs and `snapshot.json` bytes are deliberately absent. Use custody `A4_OPERATION=stage A4_STAGE=rehearsal A4_REHEARSAL_FILE=/private/rehearsal.json`, dry-run then explicit write. Custody and real attestation are the trust boundary; the parser does not independently verify signatures.
10. Validate **all** existing checkpoint inputs without writing:

    `make k8s-preprod-a4-prepare A4_PHASE=checkpoint A4_DRY_RUN=1 A4_KUBECONFIG_FILE=/private/tenant-kubeconfig A4_REQUEST_FILE=/private/request.json ENV=test-preprod-a4`

    It rechecks live SQL source/schema/journals, remote bytes, image, initial key ring/budgets, both local and object-store final backup bytes, qualification applicability and the real shipped checkpoint schema. Fresh rollback evidence stays separate from qualification evidence; candidate/logical-state drift invalidates reuse. No accepted digest is edited in place.
11. With the approved fence still held, repeat with `A4_DRY_RUN=0`. It exclusively writes the real `app-cm-identity-cutover/1`, `purpose: cutover` checkpoint, enforces 0600 and at most 32768 bytes, and reloads it with the boot validator. End this step with checkpoint/digest review against the private receipts. Preserve the approved tenant single-writer exclusion.
12. Run annex action `delete-custodian` exactly once (delete only that Pod, wait for deletion so the ReadWriteOnce PVC detaches; retain PVC/files), then `start-api` (API at the exact candidate image, one replica, rollout wait). API boot owns the import/deletion transaction. UI, IdP, other writers, CronJobs, remote-file writers and CD/GitOps remain stopped.

## Verification and release of the fence

First run `make k8s-preprod-a4-verify A4_VERIFY_PHASE=internal A4_KUBECONFIG_FILE=/private/tenant-kubeconfig A4_REQUEST_FILE=/private/request.json ENV=test-preprod-a4`. Its read-only transaction requires journal timestamp **1793577600000** with the bundled migration hash; CM receipt `0015_app_cm_identity_cutover` with preserved-material/identity/lifecycle attestations and matching source/manifest digest; D11 `a4-identity-cutover` / `pre-deletion-checkpoint` matching candidate, source, remote, mapping and rehearsal; D11 `a4-identity-cutover-completed` / `post-deletion-attestation` with `legacy_tables_dropped=true`; and absence of `public.users`. It also requires updated/available API replicas and a serving API EndpointSlice. It does not call public HTTP while UI is stopped. It prints digests, never receipt JSON.

The actual product Ingress routes **all paths to Service `ui`**; UI nginx proxies `/api` to API. After internal success, install the approved namespace-scoped Traefik `Middleware/a4-verification` and attach it to **both** `Ingress/sentropic` and `Ingress/auth-idp` with annex action `restrict`. Its `ipAllowList.sourceRange` contains only the approved operator/probe egress hosts (`/32` or `/128`), with no forwarded-header `ipStrategy`. The tenant must establish the observed client address through the actual LB/Traefik path, prove an excluded source is denied on both hosts, exclude alternate/direct access paths, and record `trafficRestrictionReceiptRef`. The verifier checks the exact live middleware spec digest and Ingress attachments; it does not independently perform the excluded-source probe. Missing CRD, ambiguous source-address behavior or unsuccessful denial proof blocks this phase; do not broaden the ranges.

Run annex `start-ui` at the approved immutable UI image, one replica, then verify with `A4_VERIFY_PHASE=http` and the digest-bound execution annex. This rechecks internal evidence, the restricted Ingress topology, UI readiness/image and that other controllers remain fenced, then requires public `/api/v1/health` **HTTP 200**. Only after that success run annex `start-idp`, one replica at the same candidate image as API, with its preserved IdP entrypoint/configuration. This is a narrow, explicitly authorized identity-writer exception for the nominated test; it does not release the general fence. Both starts refuse without the live approved restriction. Recheck HTTP and record IdP rollout plus functional evidence.

Check startup completed and no migration error through tenant-controlled log inspection; do not publish raw errors or log tails. With only API, restricted UI/proxy and restricted IdP running, perform the nominated authorized functional flow: obtain a fresh email code or magic link, complete sign-in, satisfy required MFA, access the expected account/workspace, exercise the approved refresh/revocation check, then sign out. The owner's **2026-11-05** decision invalidates old ephemeral challenges/codes/links and legacy sessions in rehearsal and cutover; replay refusal is not fresh-auth acceptance. Record functional evidence without codes/tokens, user rows or secret values. HTTP health, UI shell and IdP process health alone do not satisfy this gate.

Only after DB/D11/readiness/HTTP and functional receipts pass, run the exact annex `resume` vectors to restore approved controller states individually, including the tenant nightly backup schedule; remote writers and deployment reconciliation follow their separately enumerated compatible tenant actions. Run `open-traffic` only after all conditional acceptance is recorded. Keep G7 suspended with both dry-run legs set: account retirement and G7 activation need separate authorization. Retain rollback evidence under its approved metadata-disposition policy.

## Abort and rollback

On any missing receipt, drift, changed template, unexpected writer, corrupt snapshot, invalid key/budget, permission failure, failed rehearsal, timeout, migration error or failed auth verification: stop, run the approved `refence` vectors to stop the narrowly resumed API/UI/IdP when needed, keep traffic restricted and deployment reconciliation frozen, preserve private evidence, and do not issue/consume another checkpoint or resume other writers. There is no automatic rollback, retry with relaxed validation, or migration/journal editing.

Before import commits, the control import/deletion transaction rolls back on failure. Public migrations and settings reconciliation run earlier and may already have committed: a failed boot does not prove an unchanged database. Read journal/schema state and prove compatibility before restoring any prior image. An incomplete preparation leaves no valid checkpoint; do not overwrite its files or reuse its operation ID.

After journal/D11 show a committed cutover, an old-image rollback alone is incompatible. The tenant backup operator performs the explicitly approved whole-database restore from the validated `source.sql.gz`/tenant object and restores the agreed remote snapshot and coherent prior release, with writers still stopped. Apply the established OAuth refresh invalidation on restore, preserve HMAC/signing/connector key custody, then verify journal/schema, readiness, HTTP 200 and functional authentication again. The approved limits must state treatment of every write accepted since the snapshot. If that loss is not authorized, remain fenced and obtain the owner’s recovery decision; do not discard those writes.
