**F-CM1 — Amend: deliver the existing gateway as a shared batch profile**

Extract and qualify this implementation behind injected ports; do not build another pool. Its direct application database/environment imports (`:6`) are a packaging gap. They are not an acceptable dependency from a reusable package.

The published Node host is useful prior work, but its loopback-only listener and `FileGatewayStateStore` single writer do not satisfy this profile (`packages/llm-gateway/src/node/gateway-host.ts:23`, `:29`). Keep accounts, reservations, health and audit in shared durable control storage; keep executable credentials inside the provider-owned encrypted vault/egress boundary. Reuse session isolation, concurrency caps and serialized refresh from the federation seat contract (`.tmp/cm-federation/r5.md:473`, `:487`, `:524`). Replica-local maps cannot be the shared authority.

Amend “free the lease at deadline”: the existing account lease has no expiry field, while the reservation does (`packages/llm-mesh/src/account-transports.ts:55`). Define the batch caller/reservation deadline and bound upstream execution explicitly. A dead caller loses authority at that deadline; an upstream call with an unknown outcome must not silently release a concurrency slot or receive a second dispatch. Reclaim capacity after observed termination or the qualified hard execution bound. Preserve explicit sticky rebind and short transactions.

The relayed owner answer is **yes for Codex and Claude Code pooling, subject to terms** (`.tmp/packets/geo-fcm-assessment.md:25`); do not ask the owner to repeat it. It does not establish provider permission for the exact product, non-vendor client, hosted relay or service workload, nor authorize unrelated humans to use a personal seat. Record that qualification and the service-to-seat-owner grant. **Cloud Code remains unknown**, and is distinct from Claude Code. A Gemini fallback must name and qualify its actual transport; it cannot silently substitute for the requested Cloud Code route. Thus a Codex/Claude subset, if qualified, must be labelled partial against the original request's runtime list.

**(b) Target.** `@sentropic/cluster-mesh@0.27.0` batch composition, `@sentropic/llm-mesh@0.33.0` neutral coordination/storage contract, and `@sentropic/llm-gateway@0.23.0` as the P1 gateway tuple; reuse the private `apps/llm-gateway` host. **F-CM3 — Amend: add a trusted Kubernetes issuer binding, not a CLI dependency in Jobs**

Existing types carry tenant context but no lane/workspace claim contract (`packages/cluster-mesh/src/token-exchange.ts:43`); the client caps minted lifetime at 300 seconds and cache residence at 60 seconds (`:9`). Bind a trusted Kubernetes issuer/key set, exact audience, subject, expiry and the required bound-workload/SA identity evidence. Resolve the full verified subject by exact registration. The actual PV row is `system:serviceaccount:geo:s3dag-pv-sa` → tenant `geo`, workspace `geo-pv` (`geo:deploy/k8s/s3dag-c1-identity-workspace-map.json:23`), not a new per-run or per-node service account. Mint an opaque service principal plus authoritative tenant/workspace/lane and policy revision; do not cast a service principal into a human owner. The existing ledger already distinguishes service principals (`api/src/services/llm-metering/budget-admission.ts:146`).

Implement authenticated attest/offboard service operations over the same identity authority and audit, without a per-Job h2a process or long-lived exchange secret in pods. Freeze the workload/session-authority contract with the identity owner: current F15 has no Kubernetes workload binding (`packages/cluster-mesh/src/identity/decision.ts:46`). Offboarding denies further issuance, invalidates relevant caches and fences calls; unobserved revocation is bounded by the original token lifetime, never extended by cache use. Do not apply federation memory's offline freshness window to these tokens.

A necessary acceptance addition is the Job-creator boundary: geo explicitly warns that whoever creates a Job can select its service account, so the present lane is only an accounting label until admission policy or namespace isolation constrains that choice (`geo:packages/s3-dag/src/identity.ts:22`). **F-CM6 — Amend: domain attestation, with remote projection resolution kept gated**

**(a) Decision and evidence.** Accept signing the promotion statement and offline verification. Reuse the existing identity/key-registry trust foundation where qualified, with a purpose-scoped signing grant; do not introduce a second identity directory or silently use an identity-signing key as a general signing service. Do not transport PV bytes through cluster-mesh.

Offline verification must state its trust snapshot: it cannot know a revocation published after its last trusted key-set update. Specify key rotation, allowed algorithms/canonical bytes, key-set validity and fail-closed stale/unknown-signer behavior. Tampered bytes, wrong scope/purpose and changed policy/profile digest must fail. This is a domain receipt consumer, not permission to enable `resolve()` across servers.
